# CONTEXT

Domain + architecture vocabulary for HypoExplorer. Use these terms exactly in
code, comments, and reviews so language stays consistent. Data shapes live in
[docs/DATASET_CONTRACT.md](docs/DATASET_CONTRACT.md); this file names the concepts.

## Domain

- **Dataset** — one study/modality (macaque snRNA, mouse bulk HFD, miRNA array…). Registered in `src/data/datasets.ts`.
- **Study selection** — the studies included in a cross-dataset analysis after its capability, evidence, sample-count, category and individual-study restrictions. No individual restriction means all eligible studies; an explicitly empty individual selection means no studies.
- **Track** — the unit a user selects within a dataset: a cell population for single-cell, a whole-tissue track for bulk/miRNA.
- **Group** — an experimental arm `{ key, label, color }` (Normal, Obese, Chow, HFD…).
- **Contrast** — a baseline→case comparison between two groups; carries the DE table and (when supported) the pathway table.
- **Explorer tab scope** — what an explorer tab's content follows. **Track-scoped** tabs (Gene Explorer, Pathway Explorer, Circadian) redraw for the selected track; **dataset-scoped** tabs (Quality Control, Data Sources) describe every track of the study at once, so selecting a track while one is showing is a request to see that track.
- **Compare** — the explorer's across-tracks view of one dataset. It is not a track and carries no tab; it remembers the track and tab it was entered from and returns there when left.
- **Feature** — the row entity: a gene (default) or a miRNA. Stored under the `gene` key; `featureType`/`featureLabel` drive the UI label.
- **Ambiguous authority match** — the nomenclature status for a stored name whose active authority candidates remain unresolved. No single authority identifier or canonical alias target is implied. This qualifies identifier interpretation; it does not change measured expression or establish the study's organism.
- **Expression source** — a preparation, measurement scale and set of sample groups used for a descriptive expression survey. It may come from a registered track or stand alone as an expression-only reference; it does not imply a DE contrast.
- **Expression profile** — one measured cell, library, tissue sample or pool in an expression source. Its count describes measured profiles; independent biological replication depends on the source's animal, donor, litter or pool design.
- **Reference eligibility** — an explicit source-condition decision for the survey's eligible-reference filter. Unknown feeding state or an excluded intervention does not become eligible because a source is called a reference or its values pass an import check.
- **Current pathway provenance** — evidence that current enrichment outputs belong to the declared analysis and inputs. It is distinct from a comparison to a historical migration baseline and from agreement with author-reported pathways.
- **Retained input identity** — an expected input fingerprint preserved from fixed earlier evidence. It identifies the intended source but does not establish that the input is currently available or has been read and verified again.
- **popData** — the transformed, React-friendly view of one track (built by `src/data/buildPopData.ts`): `de`, `cpm`, `volcanoPts`, `allPathways`, resolved `contrast`, `groupSamples`, `sampleOrder`, `expressionUnit`.
- **Bundle** — a generated `.js` data file under `public/datasets/<id>/` (or `public/query/`, `public/nomenclature/`) that sets exactly one namespaced `window` global as a side effect. Loaded by `<script>` injection, not `fetch`: bundles are served cross-origin from R2 with no CORS policy. A track's FGSEA pathways ship in a **sibling bundle** (`track_<id>.pathways.js`) so the gene path never downloads them.

## Architecture

- **Sample-value seam** (`src/utils/sampleValues.ts`) — the single place that resolves a contrast's groups to their samples' positions in the `cpm` array and reads values from there. `getGroupColumns` is the indexing primitive (group → sampleId → index in `sampleOrder`, with the lone `index<0` / null-drop rule); `getGroupedValues` (chart aggregation) and `getRawSampleRows` (tidy export rows) both build on it. **Every spelling of the expression unit resolves here**: export column headers come from `valueColumnName` / `meanColumnLabel` (camel-cased, honouring `popData.expressionUnit`, adopted by ALL export sites — CSV and XLSX can no longer disagree), and on-screen labels come from `displayUnit` (`CPM` / `log2` / the unit verbatim — an unknown unit is never mislabelled CPM). **Every spelling of a group-label fallback resolves here too**: `groupLabels(contrast)` returns the `{ baselineLabel, caseLabel }` a view renders for the two arms — the contrast's own labels when it resolved, the NEUTRAL `Baseline`/`Case` when it didn't (five views used to hand-spell this fallback in three vocabularies, so a null contrast on a mouse dataset could render macaque `Normal`/`Obese` on-screen and inside a downloaded workbook). Charts and every CSV/XLSX exporter go through this seam — nothing re-implements positional sample slicing or re-derives a unit string. `sampleAxis` is the axis-shaped reader (every `sampleOrder` slot in order, tagged with its arm or null) for charts that render ALL samples including unassigned ones; the leading-edge heatmap consumes it plus `valueAt`, so no positional `cpm` read exists outside the seam.
- **Workbook seam** (`src/utils/workbook.ts`) — the single place sheet rows become a downloaded `.xlsx`: `writeWorkbook(filename, sheets)` owns the xlsx mechanics and inherits `withXLSX`'s lazy-chunk + never-reject failure policy, so export handlers are declarative sheet descriptions. The row shapes those sheets share live in `src/utils/excelExport.ts` (`rawValueRows`, `leadingEdgeSummaryRows`, `groupMeanColumns`, `pathwayInfoRows`) and read their headers through the sample-value seam. No component touches `XLSX.utils` directly.
- **Export-action seam** (`src/utils/exportAction.ts`) — the workbook seam owns what an export *writes*; this owns what an export *click* does. `useExportAction(settleMs)` is the one busy-state policy (set busy, call the handler synchronously so it reads the current render's state, settle only after the promise resolves, ignore re-entrant clicks, never fire after unmount); `exportFilename(parts, ext)` is the one spelling of the `/[\\/:*?"<>|]/g` sanitizer; `downloadFile(filename, href)` is the one `<a download>` transport (CSV data-URIs and PNG snapshots both go through it). Every export button in the app runs through this seam — no component hand-rolls a spinner timer or a filename scrub.
- **Dataset-meta value** (`src/data/datasetMeta.ts`) — the active dataset's `DatasetMeta` is a VALUE that flows from App's state as props; there is no `window.POP_META` and no module-level "active dataset". `trackColor` / `trackLabel` are the pure lookups (null meta degrades to the bare id / `#888888`, never to a stale previous dataset). Track lookups flow the same way: App hands CompareTab/QCTab a `getTrack(trackId)` closure over its namespaced cache, so no consumer learns the `${datasetId}::${trackId}` key convention. Pure utilities (`getCellSubname`, `groupByType`) take their maps as required inputs.
- **Registry factory** (`defineDataset` in `src/data/datasets.ts`) — the seven bundle-locator fields (`metaFile`, `metaGlobalKey`, `qcFile`, `qcGlobalKey`, `bundleFileTemplate`, `globalKeyTemplate`, `bundleBaseUrl`) are derived from `id` by the factory (all overridable per entry); an entry states only what differs per dataset. `category` is a REQUIRED manifest field typed against `DATASET_CATEGORIES` (`src/data/datasetCategories.ts`, dependency-free so the Dataset type can require it) — `datasetCategory(id)` throws on unknown ids rather than silently mis-stratifying the meta-analysis. `datasets.ts` is the manifest plus the registry lookups, nothing else: contrast resolution (`getActiveContrast` / `listContrasts` / `requireContrast`, `src/data/contrasts.ts`) and the URL/global-key locators (`src/data/bundleLocators.ts`, DOM-free and registry-free like `bundleBase.ts`) are pure functions of a `Dataset` VALUE and live in their own modules.
- **Author-validation sidecar** (`data/author-validation/validation-records.generated.json`; typed adapter `src/data/authorValidation.ts`) — the registry-id keyed ledger that keeps three claims separate: `pipelineTrace` proves every public bundle row traces to the committed analysis output; `processed_source_match` proves the local input matches the author-deposited processed source; `author_result_match` requires a direct comparison with the author's own result table. `validated_with_notes`, `review_required`, `source_unavailable`, `in_progress`, and the explicit macaque-single-cell `not_applicable` state prevent either weaker evidence or missing access from being rendered as a pass. The sidecar has exact registry closure and ships in the app bundle, so `datasetCatalog` attaches it on the first frame and the library/tracker never wait on the remote query manifest. `refresh_author_source_inventory.mts`, `audit_author_validation.mts`, and `compare_author_results.mts` generate the evidence layers; `build_author_validation.mts --require-complete` joins them with `manual-review.json` and fails while any in-scope audit is still `in_progress` (resolved `review_required` records remain valid, visible blockers). Paper access is recorded independently from processed-data access, including PMC, publisher-open, PubMed-only, unlinked, and embargoed cases.
- **Page shell + forest primitives** — `src/common/PageShell.tsx` owns the full-page chrome (4px accent strip, sticky 46px header, logo, Home breadcrumbs) for CrossDatasetCompare, GeneReport, PathwayReport and StatisticsView; the explorer shell, hub and tracker keep their own structurally different chrome. `src/crossdataset/forestReport.tsx` holds what the cross-dataset report pages genuinely share (`axisPct`, direction encoding, `SigPill`, `contrastLabel` — which reads the label `resolveContrast` already produced, never re-derives it — `groupForestCategories`, `useReportQuery`, `useCategoryScope` + `FilterChip` for the category-scope chips, the `FOREST_GRID` template) — deliberately NOT one all-owning `<ForestReport>`: each report keeps its own `ForestRow`, because GeneReport's CI whiskers / pooled rows / disclosures are gene-domain policy a shared schema would have to expose as interface. All three report views (CrossDatasetCompare included) run their load lifecycle — cancelled-flag, loading/error, progress — through `useReportQuery`; none hand-writes it.
- **Bundle-source seam** (`src/data/bundleSource.ts`) — the single place a bundle URL + window-global name becomes a value. Owns the `<script>` injection, the one bundle cache (keyed by **URL**, not global key — query shards reuse a global name across build ids), in-flight dedup, and the `?v=` cache-bust. Two entry points, not one with a flag, so the failure policy is part of the in-flight identity: `loadRequiredBundle` rejects and never caches the failure (a transient error stays retryable); `loadOptionalBundle` resolves `null`, caching the miss only when it is deterministic (script loaded, global unset) — a failed load stays retryable on both paths, because a `<script>` onerror cannot tell a 404 from a network blip and a cached blip would pin the session to the degraded path. The transport is swappable via `_setBundleTransport` — the script-tag adapter in the browser, a map-backed one in tests — and `_resetBundleCache` bumps a generation counter so a load still in flight cannot repopulate a cache that was just cleared. `peekGlobalBundle` is the seam's synchronous companion — the one spelling of "read an eager global off `window`" (index.html's first-paint seeds, the tracker catalog); no module reads `window.X` inline. `BUNDLE_BASE` lives in `src/data/bundleBase.ts`, kept DOM-free because the Node scripts type-check `datasets.ts`. Every dataset's `bundleBaseUrl` is a projection of it. **`/tracker/catalog.js` is deliberately origin-relative** — the build prunes only `dist/datasets/`, `dist/query/`, and `dist/qc/` for off-origin deploys.
- **Track-data seam** (`src/data/trackData.ts`) — the single place a (dataset, trackId) becomes a loaded track, and a loaded track becomes popData. `loadTrackData(dataset, trackId, { pathways })` owns the whole load protocol that used to be spelled out at each call site: bundle fetch → sibling-bundle hydration → in-place attach to the stable raw → transform-cache invalidation. The **pathway policy is a required argument**, so a pathway-less view (the cross-dataset gene query) is a stated choice rather than a forgotten step. `pathwaysReady` resolves the raw when there is something new to re-read and `null` when there is not; it deliberately carries no prebuilt popData, because the sibling can land after the user has switched contrast. `popDataFor(raw, dataset, contrast)` is the synchronous read, memoized per (raw, dataset, contrast) — **dataset and contrast are required**: when they were optional the transform silently fell back to the macaque atlas, which is how the Compare tab came to render the wrong contrast. Everything that needs popData goes through this seam; `loadTrack` / `popCache` are its implementation.
- **Explorer store** (`src/data/explorerStore.ts`) — the single place the explorer's per-dataset resources are loaded and held (the dataset's `DatasetMeta`, its `QcGlobal`, and the cache of loaded tracks), and the single place a late resolve is dropped. `useExplorerStore({ dataset, activeTrackId, wantQC })` takes what is ACTIVE as input — navigation stays the shell's — and owns everything that follows: the dataset-namespaced track cache (keyed `${datasetId}::${trackId}`, private to the module, so `getTrack` takes a bare track id), the React-layer in-flight dedup above `loadTrack`'s, the eager-global seed for the default dataset's first paint, the loading/error banner state, and `retry`. The **stale-write guard is written once** here; it was hand-written five times in App (meta ×3, QC ×2), and one copy compared a closure-captured id against itself — a guard that could never fire. `quiet` loads never drive the global overlay; Compare no longer uses them (it loads through the track-column module), so the store serves the main explorer alone. Sits ABOVE the track-data seam, which still owns the load protocol itself.
- **App router** (`src/appRouter.ts`) — the single place that answers "where is the user, and how do they get somewhere else". Owns the `AppView` union (see the generated context map for the current view inventory), the parameters each view was opened with (`reportGene` / `reportScope` / `reportPathway` / `trackerSelectedAcc`), every navigation verb, and the `#/dataset/<id>[/<trackId>]` deep-link reader. The URL is a two-way binding: `parseRoute` reads links, `routeHref` serializes them, and navigation writes through history APIs while suppressing writes during route landing. Incoming routes are treated as **untrusted input**: an unknown dataset is ignored and an unknown track degrades to the dataset's default, so a stale link never lands on a 404'd track behind an error banner. The router decides WHERE; an `ExplorerNavigation` adapter passed in by the shell takes one whole **navigation intent** (`navigate(intent)`) and the shell's explorer position decides HOW it lands — which is what keeps the router free of the shell's own state. Compare round-trips as `#/dataset/<id>/compare` (no tab segment); the router checks that the dataset has two populations before landing it. That adapter is read through a ref so the verbs stay referentially stable while still routing through the latest adapter; without it every memoized hub tile would re-render on an unrelated explorer keystroke.
- **Explorer position** (`src/explorer/explorerPosition.ts`) — the single place the explorer's dataset, track-or-Compare, contrast and tab are held and moved. Callers never set a field: they send a **navigation intent** (`open` from outside the explorer, `track`, `compare` / `leaveCompare`, `tab`, `contrast`) and `nextPosition` returns the next position plus what the move costs — the session reset scope (`RESET_MATRIX`) and the track to load — which the shell carries out. The tab rule is stated once: selecting a track keeps a track-scoped tab the new track offers and sends a dataset-scoped tab to the Gene Explorer; an `open` lands on the Gene Explorer unless a tab is named; a tab named during Compare leaves Compare for its return track. Track ids are trusted here — the untrusted-URL population check stays in the router. Compare is a `focus` kind inside the position and is spelled `COMPARE_TRACK` only at the edges that speak in track ids (the store, the sidebar, the URL).
- **Cell navigator** (`src/explorer/CellNavigator.tsx`) — the explorer's track sidebar: category grouping, the search filter, and track selection. `matchesCellQuery` deliberately spans track id, marker-gene label and category, because users arrive with any of the three ("e9", "POMC", "GABAergic"). The grouping/filter/count derivations live WITH the markup that consumes them; in App they sat ~230 lines away from it.
- **Pathway-table seam** (`src/pathway-explorer/pathwayTable.ts`) — the single place a list of FGSEA rows becomes the page of rows a table renders: DB filter → search → sort → paginate, plus "drop the selection when it falls out of the filtered list". `usePathwayTable` is generic over the row type, because the single-track Pathway Explorer pages over `PathwayRecordWithDb` while the Compare view pages over its own per-population shape; all the seam requires is that a row can be identified — and **identity is `(db, pathway)`, never `pathway` alone**, since GO and Reactome both publish a "Glycolysis". A view's own extra filter arrives as an `include` predicate (the single-track FDR cutoff), so the seam never learns which statistic a view cuts on. `PATHWAY_SORTS` holds the standard orders as data: `nes` ranks by effect size, `pval` by adjusted significance, `rawpval` by the unadjusted p — three different questions, not interchangeable. Both views previously carried verbatim copies of all of this, including a shared defect: `useEffect(() => setPage(1), [])` — an empty dependency array under a comment promising a reset when the filters change, masked by the page clamp. The reset is real here, and `safePage` still clamps.
- **Bundle-writer seam** (`scripts/lib/bundleWriter.mts`) — the WRITE-side twin of `bundleLocators.ts`: the single place a builder's payload becomes bundle files. Derives every filename and window-global key from the registry `Dataset` value (never hand-spelled templates), owns wire slimming, the pathway-sibling shape (plain vs `{default, byContrast}`), the `pathways_index` name-union, and JSONP composition. Builder manifests are ASSERTION inputs, not derivations: the writer throws when a manifest's `trackId`, arm keys, or full contrast `{id, baseline, case}` bindings disagree with the registry, and preflights all output paths/keys for pairwise collisions and identifier validity. Like the builders it replaced, it does not delete stale files (an offline-checker concern). The writer↔reader contract is pinned by a round-trip test (`bundleWriter.test.ts`) instead of prose alone.
- **Bulk-study constructor** (`defineBulkStudy` in `src/data/datasets.ts`) — the registry factory's second, narrower form: a single-track, single-default-contrast, two-arm public-expression study states only what differs (id, facets, citation, track, arm labels, contrast id); the constructor supplies the standard arm palette (`BASELINE_COLOR`/`CASE_COLOR`, named once), the lone default contrast, feature/pathway defaults, and derives `timeSeries.tracks` from the entry's own track. The macaque atlas and GSE135639 stay on `defineDataset` because they do not fit that shape. The fully-resolved registry is pinned by a committed golden (`datasetsRegistry.test.ts` + snapshot): a failure there means fix the entry, NEVER regenerate the snapshot.
- **Index-freshness seam** (`src/data/indexFreshness.ts`) — the single place "does this query-index manifest describe this registry" is answered. Consumers declare the facts they depend on (`coverage`, `trackCounts`, `defaultTrack`, `contrast`, `exprScaffold`); predicates live once; an UNVERIFIABLE need fails and the caller degrades to the slow-but-right per-track path (per-card for the library, all-or-nothing for reports — policy stays with the caller). The per-track fallback itself follows the contract rule in both directions: a non-default contrast is served only from its explicit `deByContrast`/`byContrast` block, while the registered default's table is `de`/the sibling's `default` block (the committed GSE135639 shape); a bundle predating a registry default swap is the manifest check's problem, not the reader's. `pnpm exec tsx scripts/check_datasets.mts` runs the same closure offline (locator-named files, manifest at full strictness, tracker sidecars bidirectionally against the documented accession alias sets, arm coverage; default tracks only — pass `--all-tracks` to parse every track) — read-only, and structural: value-level closure stays `build_query_index.mts --check`.
- **Arm-count + arm-pill seam** (`contrastArmCounts` in `src/data/contrasts.ts`; `ArmPills`/`ArmVariesBadge` in `src/common/StudyMetadata.tsx`) — the single derivation of "how many replicates in this arm" for the ACTIVE contrast (tiers: loaded membership ∩ QC-kept, `groupN`, loaded QC, meta `qcFlags`; null renders '–'), sharing its per-arm tier helper with `defaultArmCounts` (which stays independent — its caller supplies the pooled pair). ArmPills is the ONLY spelling of the replicate pill (sm/md/lg + the countless `design` variant); no view hand-rolls a pill, a wash alpha, or an "n varies" badge.
- **QC table specs** (`src/qc/qcTables.ts`) — QCTab's six row/column derivations as pure, React-free spec builders over TYPED `QcGlobal`/`DatasetMeta` (the `as QcRow` any-wall is gone); `qcVocabulary` owns the de-macaqued arm labels and the legacy normal/obese fallback, building on `groupLabels`. QCTab injects JSX renderers per column key and renders the specs; the generic sortable-table chrome lives in `src/common/SortableTable.tsx`.
- **Track-column module** (`src/data/trackColumns.ts`) — the single place a track a view has asked for moves through its load lifecycle: `loading → ready | failed | unknown-track`, with error text, a per-column `retry` (from any state, so a failed pathway sibling is re-asked) and `pathwaysSettled`. popData is a render-time read (`popDataFor` at the request's CURRENT contrast), never stored, so a contrast switch reloads nothing and a hydrated sibling needs no re-read message. Both policies are required arguments: `pathways` (`include` / `omit`) and `trackList` (`verify` reads meta.js and is the only source of `unknown-track`; `trust` is for ids taken from the dataset's own track list or index rows). Kept columns never reload. Compare, the compare set (through the thin `useCompareSetColumns` adapter) and both report previews go through it; it sits on the track-data seam and deliberately NOT under the explorer store, whose cache, seed and overlay belong to the main explorer. It replaced the store's quiet path for Compare, whose catch swallowed a failed bundle into an endless "Loading X…".
- **Export-provenance seam** (`src/utils/exportProvenance.ts`) — the single place an export says what it is evidence of. A view supplies a kind, its own settings and a subject (`trackSubject`, `timeSeriesSubject`, `columnsSubject`, or `localExportProvenance` for imported data); the module owns the filename identity (`exportName`: dataset, track, contrast(s), kind — so two contrasts never save over each other), the snapshot (release, dataset, accession, contrasts and direction, unit, retained evidence, groups, settings, source link, reuse), the Metadata sheet (`metadataSheet`) and the CSV columns (`provenanceColumns`). Absences stay explicit: a missing contrast is `unresolved-contrast`, a time course says "Not applicable", and a local dataset says it has no release, evidence or licence — except a local copy of PUBLIC results (`public:<dataset>:<track>:<contrast>`), which names the study it was copied from and says its release and evidence were not retained with the copy; a copy the user has added their own files to says it is mixed, so imported rows are never attributed to the public study. Sits beside the workbook and export-action seams; no view hand-names a file or writes its own settings sheet.
- **Gene selection** (`src/explorer/geneVocabulary.ts`; `src/common/GenePicker.tsx`) — the single place a picked name becomes a selected gene. A **vocabulary** is one track's symbols, the union of a dataset's loaded populations, or a case-folded union across studies; it owns the case policy (`keyOf`: exact, then the stored spelling case-insensitively, as `resolveGeneList` does; upper-case across studies so POMC and Pomc are one gene), the shared nomenclature authority (null when species are mixed, so redirects fail closed) and per-chip nomenclature facts read per source in that source's own namespace — the dataset's stored-symbol authority (`nomenclatureAuthorityForStoredDatasetSymbols`), and none at all for a source without one, so no chip borrows a namespace its study never used. `useBoundGeneSelection` routes `add` / `addMany` / `replace` through it over a `useGeneSelection` instance, whose state and resets stay in the explorer session. `GenePicker` is the one picker view (search, gene-list tools, count, Clear all, chips with the "now X" note) in the Gene Explorer, Compare tab and compare set.
- **Gene-list seam** (`src/utils/geneListFile.ts`; `src/common/GeneListTools.tsx`) — the single place a FILE becomes a list of symbols and a selection becomes a file. `parseGeneListFile` / `parseGeneListText` detect the shape from the extension (workbooks go to the lazily-loaded xlsx, GMT has a fixed field order) and otherwise from the content: the delimiter that runs through most lines (none → whitespace, which is what makes a pasted `POMC AGRP NPY` work), the gene column by a recognised header (`GENE_HEADER`: Gene, Symbol, gene_name, GeneID, …) or, headerless, by which column's cells look like symbols; `#` comments, blank cells and R's `NA` are dropped, and a one-line paste is a list rather than a one-row table. `resolveGeneList` then maps the file's names onto the DATASET's own spelling — case-insensitively, then through the alias index exactly as `GeneSearchBox` does for one gene — and reports `found` / `redirected` / `missing` / `ambiguous` (an alias shared by several stored genes fails closed) so a list dropped on the wrong species says which names it could not place instead of silently selecting fewer. `saveGeneList` writes txt (one symbol per line), csv or xlsx through the export-action and workbook seams. `LoadGeneListButton` and `SaveGeneListMenu` sit in the shared `GenePicker` (gene selection, below) in the Gene Explorer, Compare tab and compare set; `SaveGeneListMenu` alone serves the volcano's threshold-passing list, whose rows carry direction, log2FC, p and FDR.
