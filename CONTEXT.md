# CONTEXT

Domain + architecture vocabulary for HypoExplorer. Use these terms exactly in
code, comments, and reviews so language stays consistent. Data shapes live in
[docs/DATASET_CONTRACT.md](docs/DATASET_CONTRACT.md); this file names the concepts.

## Domain

- **Dataset** — one study/modality (macaque snRNA, mouse bulk HFD, miRNA array…). Registered in `src/data/datasets.ts`.
- **Study selection** — the studies included in a cross-dataset analysis after its capability, evidence, sample-count, category and individual-study restrictions. No individual restriction means all eligible studies; an explicitly empty individual selection means no studies.
- **Track** — the unit a user selects within a dataset: a cell population for single-cell, a whole-tissue track for bulk/miRNA.
- **Group** — an experimental arm `{ key, label, color }` (Normal, Obese, Chow, HFD…).
- **Contrast** — a baseline→case comparison between two groups; carries the DE table and (when supported) the pathway table.
- **Significance tier** — a result's standing against the app's fixed cutoffs: `fdr` (passes FDR < 0.05, a discovery), `nominal` (raw p < 0.05 but not FDR, uncorrected and labelled "p < 0.05 only") or `none`. A fact about the result, so its label never depends on the listing mode. _Avoid_: "significant" for the nominal tier.
- **Listing mode** — the reader's choice of what a cross-study view leads with: FDR results alone, or FDR results followed by the nominal tier. It changes what leads, the order and what is counted, never a row's tier.
- **Cross-study listing** — one term's results across a study selection, arranged for a listing mode: the rows that lead, the rest in order, and the track and dataset counts. Search summaries, the gene report and the pathway report all present a cross-study listing; each decides only how much of it to show and what starts folded. A dataset that was selected but has no measured result still counts toward the selection, not toward the listing.
- **Explorer tab scope** — what an explorer tab's content follows. **Track-scoped** tabs (Gene Explorer, Pathway Explorer, Circadian) redraw for the selected track; the **dataset-scoped** tab (Quality Control) describes every track of the study at once, so selecting a track while one is showing is a request to see that track.
- **Compare** — the explorer's across-tracks view of one dataset. It is not a track and carries no tab; it remembers the track and tab it was entered from and returns there when left.
- **Feature** — the row entity: a gene (default) or a miRNA. Stored under the `gene` key; `featureType`/`featureLabel` drive the UI label.
- **Ambiguous authority match** — the nomenclature status for a stored name whose active authority candidates remain unresolved. No single authority identifier or canonical alias target is implied. This qualifies identifier interpretation; it does not change measured expression or establish the study's organism.
- **Expression source** — a preparation, measurement scale and set of sample groups used for a descriptive expression survey. It may come from a registered track or stand alone as an expression-only reference; it does not imply a DE contrast.
- **Expression profile** — one measured cell, library, tissue sample or pool in an expression source. Its count describes measured profiles; independent biological replication depends on the source's animal, donor, litter or pool design.
- **Reference eligibility** — an explicit source-condition decision for the survey's eligible-reference filter. Unknown feeding state or an excluded intervention does not become eligible because a source is called a reference or its values pass an import check.
- **Current pathway provenance** — evidence that current enrichment outputs belong to the declared analysis and inputs. It is distinct from a comparison to a historical migration baseline and from agreement with author-reported pathways.
- **Retained input identity** — an expected input fingerprint preserved from fixed earlier evidence. It identifies the intended source but does not establish that the input is currently available or has been read and verified again.
- **popData** — the transformed, React-friendly view of one track (built by `src/data/buildPopData.ts`): `de`, `cpm`, `volcanoPts`, `allPathways`, resolved `contrast`, `groupSamples`, `sampleOrder`, `expressionUnit`.
- **Bundle** — a generated `.js` data file under `public/datasets/<id>/` (or `public/query/`, `public/nomenclature/`) that sets exactly one namespaced `window` global as a side effect. Loaded by `<script>` injection, not `fetch`: bundles are served cross-origin from R2 with no CORS policy. A track's FGSEA pathways ship in a **sibling bundle** (`track_<id>.pathways.js`) so the gene path never downloads them.

## Architecture

- **Sample-value seam** (`src/utils/sampleValues.ts`) — the single place that resolves a contrast's groups to their samples' positions in the `cpm` array and reads values from there. `getGroupColumns` is the indexing primitive (group → sampleId → index in `sampleOrder`, with the lone `index<0` / null-drop rule); `getGroupedValues` (chart aggregation) and `getRawSampleRows` (tidy export rows) both build on it. **Every spelling of the expression unit resolves here**: export column headers come from `valueColumnName` / `meanColumnLabel` (camel-cased, honouring `popData.expressionUnit`, adopted by ALL export sites — CSV and XLSX can no longer disagree), and on-screen labels come from `displayUnit` (`CPM` / `log2` / the unit verbatim — an unknown unit is never mislabelled CPM). **Every spelling of a group-label fallback resolves here too**: `groupLabels(contrast)` returns the `{ baselineLabel, caseLabel }` a view renders for the two arms — the contrast's own labels when it resolved, the NEUTRAL `Baseline`/`Case` when it didn't (five views used to hand-spell this fallback in three vocabularies, so a null contrast on a mouse dataset could render macaque `Normal`/`Obese` on-screen and inside a downloaded workbook). Charts and every CSV/XLSX exporter go through this seam — nothing re-implements positional sample slicing or re-derives a unit string. `sampleAxis` is the axis-shaped reader (every `sampleOrder` slot in order, tagged with its arm or null) for charts that render ALL samples including unassigned ones; the leading-edge heatmap consumes it plus `valueAt`, so no positional `cpm` read exists outside the seam.
- **Workbook seam** (`src/utils/workbook.ts`) — the single place sheet rows become a downloaded `.xlsx`: `writeWorkbook(filename, sheets)` owns the xlsx mechanics and inherits `withXLSX`'s lazy-chunk + never-reject failure policy, so export handlers are declarative sheet descriptions. The row shapes those sheets share live in `src/utils/excelExport.ts` (`rawValueRows`, `leadingEdgeSummaryRows`, `groupMeanColumns`, `pathwayInfoRows`) and read their headers through the sample-value seam. No component touches `XLSX.utils` directly.
- **Export-action seam** (`src/utils/exportAction.ts`) — the workbook seam owns what an export *writes*; this owns what an export *click* does. `useExportAction(settleMs)` is the one busy-state policy (set busy, call the handler synchronously so it reads the current render's state, settle only after the promise resolves, ignore re-entrant clicks, never fire after unmount); `exportFilename(parts, ext)` is the one spelling of the `/[\\/:*?"<>|]/g` sanitizer; `downloadFile(filename, href)` is the one `<a download>` transport (CSV data-URIs and PNG snapshots both go through it). Every export button in the app runs through this seam — no component hand-rolls a spinner timer or a filename scrub.
- **CSV seam** (`src/utils/csv.ts`) — the CSV twin of the workbook seam: `writeCsv(filename, columns, rows, { provenance? })` is the single place a table becomes a downloaded `.csv`. It owns the one byte policy (UTF-8 BOM, CRLF after every record including the last, a cell quoted only when it holds `,` `"` CR or LF, null/undefined as an empty cell), the **spreadsheet formula guard** (a STRING cell starting with `=` `+` `-` `@` after optional whitespace, or with a tab or CR, gets a leading `'`; numbers are never prefixed, nor is a string that is just a decimal number such as `-1.25`), the layout of the export-provenance seam's `provenanceColumns` after the caller's own columns (`ExportMetadataJSON` once, in the first data row), and the hand-off through `downloadFile`. Callers name the file (`exportFilename` / `exportName`) and supply rows as arrays in column order; no view escapes a cell or joins a line. The expression survey still writes its own always-quoted CSV.
- **Dataset-meta value** (`src/data/datasetMeta.ts`) — the active dataset's `DatasetMeta` is a VALUE that flows from App's state as props; there is no `window.POP_META` and no module-level "active dataset". `trackColor` / `trackLabel` are the pure lookups (null meta degrades to the bare id / `#888888`, never to a stale previous dataset). Track lookups flow the same way: App hands CompareTab/QCTab a `getTrack(trackId)` closure over its namespaced cache, so no consumer learns the `${datasetId}::${trackId}` key convention. Pure utilities (`getCellSubname`, `groupByType`) take their maps as required inputs.
- **Registry factory** (`defineDataset` in `src/data/datasets.ts`) — the seven bundle-locator fields (`metaFile`, `metaGlobalKey`, `qcFile`, `qcGlobalKey`, `bundleFileTemplate`, `globalKeyTemplate`, `bundleBaseUrl`) are derived from `id` by the factory (all overridable per entry); an entry states only what differs per dataset. `category` is a REQUIRED manifest field typed against `DATASET_CATEGORIES` (`src/data/datasetCategories.ts`, dependency-free so the Dataset type can require it) — `datasetCategory(id)` throws on unknown ids rather than silently mis-stratifying the meta-analysis. `datasets.ts` is the manifest plus the registry lookups, nothing else: contrast resolution (`getActiveContrast` / `listContrasts` / `requireContrast`, `src/data/contrasts.ts`) and the URL/global-key locators (`src/data/bundleLocators.ts`, DOM-free and registry-free like `bundleBase.ts`) are pure functions of a `Dataset` VALUE and live in their own modules.
- **Author-validation sidecar** (`data/author-validation/validation-records.generated.json`; typed adapter `src/data/authorValidation.ts`) — the registry-id keyed ledger that keeps three claims separate: `pipelineTrace` proves every public bundle row traces to the committed analysis output; `processed_source_match` proves the local input matches the author-deposited processed source; `author_result_match` requires a direct comparison with the author's own result table. `validated_with_notes`, `review_required`, `source_unavailable`, `in_progress`, and the explicit macaque-single-cell `not_applicable` state prevent either weaker evidence or missing access from being rendered as a pass. The sidecar has exact registry closure and ships in the app bundle, so `datasetCatalog` attaches it on the first frame and the library/tracker never wait on the remote query manifest. `refresh_author_source_inventory.mts`, `audit_author_validation.mts`, and `compare_author_results.mts` generate the evidence layers; `build_author_validation.mts --require-complete` joins them with `manual-review.json` and fails while any in-scope audit is still `in_progress` (resolved `review_required` records remain valid, visible blockers). Paper access is recorded independently from processed-data access, including PMC, publisher-open, PubMed-only, unlinked, and embargoed cases.
- **Study-selection module** (`src/crossdataset/studySelection.ts`; value and URL form `src/crossdataset/studySelectionLink.ts`; view `src/crossdataset/StudySelectionPanel.tsx`) — the single place a report's **study selection** is held as a value, derived and written down, parameterized by report kind (`gene` / `pathway`; a pathway report only lists pathway-capable studies). The value is `{ categories, datasetIds, filters }`; the router stores ONE per report kind (the gene page's path scope is its `categories`, not separate state) and App hands it with the router's own setter straight to the report. `useStudySelection({ kind, term, value, onChange })` owns the catalog wait (a sample minimum holds the query until measured counts settle; unknown counts fail it), the eligible, available and selected studies, the typed `query` (`{ term, datasets }` read from the registry, its identity stable while the term and selected ids are unchanged, null when idle — no report decodes a key), `visibleGroups`, the category toggle (an emptied list widens to all), the functional individual-study setter and `reset`. **An explicitly empty individual selection never widens**, including a link whose studies have all left the registry. `selectionFromLink` / `selectionLink` are its URL form: the gene page writes categories into its path and a snapshot only for other restrictions or a non-native chart scale; the pathway report has no path scope; the snapshot's field order is the public version-1 format. Boot and Back/Forward read links through the same function. The value and URL form sit in their own file because the router is in the entry bundle and the derivation hook's catalog and quality imports pull in both evidence ledgers; the router imports only `studySelectionLink.ts`, and `lazyChunkBoundaries.test.ts` fails if the entry graph reaches either ledger. `StudySelectionPanel` is the one "Study filters" disclosure both reports render; only its count wording differs. Both reports' error boundaries are keyed on the term alone, so a selection change re-queries in place.
- **Page shell + forest primitives** — `src/common/PageShell.tsx` owns the full-page chrome (4px accent strip, sticky 46px header, logo, Home breadcrumbs) for GeneReport, PathwayReport and the reference pages; the explorer shell, hub and tracker keep their own structurally different chrome. `src/crossdataset/forestReport.tsx` holds what the cross-dataset report pages genuinely share (`axisPct`, direction encoding, `SigPill`, `contrastLabel` — which reads the label `resolveContrast` already produced, never re-derives it — `groupForestCategories`, `useReportQuery`, `FilterChip`, the `FOREST_GRID` template) — deliberately NOT one all-owning `<ForestReport>`: each report keeps its own `ForestRow`, because GeneReport's CI whiskers / pooled rows / disclosures are gene-domain policy a shared schema would have to expose as interface. Both report views run their load lifecycle — cancelled-flag, loading/error, progress — through `useReportQuery`, keyed on the typed request study selection hands them; none hand-writes it.
- **Bundle-source seam** (`src/data/bundleSource.ts`) — the single place a bundle URL + window-global name becomes a value. Owns the `<script>` injection, the one bundle cache (keyed by **URL**, not global key — query shards reuse a global name across build ids), in-flight dedup, and the `?v=` cache-bust. Two entry points, not one with a flag, so the failure policy is part of the in-flight identity: `loadRequiredBundle` rejects and never caches the failure (a transient error stays retryable); `loadOptionalBundle` resolves `null`, caching the miss only when it is deterministic (script loaded, global unset) — a failed load stays retryable on both paths, because a `<script>` onerror cannot tell a 404 from a network blip and a cached blip would pin the session to the degraded path. The transport is swappable via `_setBundleTransport` — the script-tag adapter in the browser, a map-backed one in tests — and `_resetBundleCache` bumps a generation counter so a load still in flight cannot repopulate a cache that was just cleared. `peekGlobalBundle` is the seam's synchronous companion — the one spelling of "read an eager global off `window`" (index.html's first-paint seeds, the tracker catalog); no module reads `window.X` inline. `BUNDLE_BASE` lives in `src/data/bundleBase.ts`, kept DOM-free because the Node scripts type-check `datasets.ts`. Every dataset's `bundleBaseUrl` is a projection of it. **`/tracker/catalog.js` is deliberately origin-relative** — the build prunes only `dist/datasets/`, `dist/query/`, and `dist/qc/` for off-origin deploys.
- **Expression-source reader** (`src/expression-survey/sourceJson.ts`) — the single transport for the survey's release-local JSON (NeuroSeq, the OXT reference, GTEx/HPA/Allen): `sourceJson(family, path)` owns the per-family file allow-list (a manifest path cannot reach another family or leave its root), the `?v=` app-version cache-bust, one session cache, forget-on-failure and the one test reset (`resetSourceRequests`). Each family's loader (`loadNeuroseqExpression`, `loadReferenceExpression`, `loadExternalExpression`) keeps its own validation and returns `ExpressionGeneResult`s. The search/gene page's NeuroSeq teaser (`loadBaselineTeaser`) is a PROJECTION of `loadNeuroseqExpression`'s per-population results — one row per source group with the survey's group mean, never a pooled population mean, ambiguity candidates spelled as the survey spells them — so the two cannot disagree. The HypoMap atlas client (`src/search/hypomap/atlas.ts`) keeps its own transport: cross-origin, immutable release-tag paths with SHA-256 checks.
- **Track-data seam** (`src/data/trackData.ts`) — the single place a (dataset, trackId) becomes a loaded track, and a loaded track becomes popData. `loadTrackData(dataset, trackId, { pathways })` owns the whole load protocol that used to be spelled out at each call site: bundle fetch → sibling-bundle hydration → in-place attach to the stable raw → transform-cache invalidation. The **pathway policy is a required argument**, so a pathway-less view (the cross-dataset gene query) is a stated choice rather than a forgotten step. `pathwaysReady` resolves the raw when there is something new to re-read and `null` when there is not; it deliberately carries no prebuilt popData, because the sibling can land after the user has switched contrast. `popDataFor(raw, dataset, contrast)` is the synchronous read, memoized per (raw, dataset, contrast) — **dataset and contrast are required**: when they were optional the transform silently fell back to the macaque atlas, which is how the Compare tab came to render the wrong contrast. Everything that needs popData goes through this seam; `loadTrack` / `popCache` are its implementation.
- **Explorer store** (`src/data/explorerStore.ts`) — the single place the explorer's per-dataset resources are loaded and held (the dataset's `DatasetMeta`, its `QcGlobal`, and the cache of loaded tracks), and the single place a late resolve is dropped. `useExplorerStore({ dataset, activeTrackId, wantQC })` takes what is ACTIVE as input — navigation stays the shell's — and owns everything that follows: the dataset-namespaced track cache (keyed `${datasetId}::${trackId}`, private to the module, so `getTrack` takes a bare track id), the React-layer in-flight dedup above `loadTrack`'s, the eager-global seed for the default dataset's first paint, the loading/error banner state, and `retry`. The **stale-write guard is written once** here; it was hand-written five times in App (meta ×3, QC ×2), and one copy compared a closure-captured id against itself — a guard that could never fire. `quiet` loads never drive the global overlay; Compare no longer uses them (it loads through the track-column module), so the store serves the main explorer alone. Sits ABOVE the track-data seam, which still owns the load protocol itself.
- **App router** (`src/appRouter.ts`) — the single place that answers "where is the user, and how do they get somewhere else". Owns the `AppView` union (see the generated context map for the current view inventory), the parameters each view was opened with (`reportGene` / `reportPathway` / `trackerSelectedAcc`, and one study selection per report kind), every navigation verb, and the `#/dataset/<id>[/<trackId>]` deep-link reader. The URL is a two-way binding: `parseRoute` reads links, `routeHref` serializes them, and navigation writes through history APIs while suppressing writes during route landing. Incoming routes are treated as **untrusted input**: an unknown dataset is ignored and an unknown track degrades to the dataset's default, so a stale link never lands on a 404'd track behind an error banner. The router decides WHERE; an `ExplorerNavigation` adapter passed in by the shell takes one whole **navigation intent** (`navigate(intent)`) and the shell's explorer position decides HOW it lands — which is what keeps the router free of the shell's own state. Compare round-trips as `#/dataset/<id>/compare[/pathways]?pops=…&genes=…`: its sub-tab is the path's last segment and its populations and genes are query lists (`CompareViewState`, defaults left out, so an untouched Compare stays `/compare`). The router checks that the dataset has two populations before landing it and drops population ids the dataset lacks; the shell remounts CompareTab on a landed view and resumes the last view when Compare is re-entered. That adapter is read through a ref so the verbs stay referentially stable while still routing through the latest adapter; without it every memoized hub tile would re-render on an unrelated explorer keystroke.
- **Explorer position** (`src/explorer/explorerPosition.ts`) — the single place the explorer's dataset, track-or-Compare, contrast and tab are held and moved. Callers never set a field: they send a **navigation intent** (`open` from outside the explorer, `track`, `compare` / `leaveCompare`, `tab`, `contrast`) and `nextPosition` returns the next position plus what the move costs — the session reset scope (`RESET_MATRIX`) and the track to load — which the shell carries out. The tab rule is stated once: selecting a track keeps a track-scoped tab the new track offers and sends a dataset-scoped tab to the Gene Explorer; an `open` lands on the Gene Explorer unless a tab is named; a tab named during Compare leaves Compare for its return track. Track ids are trusted here — the untrusted-URL population check stays in the router. Compare is a `focus` kind inside the position and is spelled `COMPARE_TRACK` only at the edges that speak in track ids (the store, the sidebar, the URL).
- **Explorer session** (`src/explorer/explorerSession.ts`) — the single place the explorer's selected and configured state (the gene selection, the volcano view, the pathway view, the sidebar filter) is held, reset and written down. `RESET_MATRIX` is what each navigation clears. The **analysis snapshot** has both sides here: `snapshot(context)` turns the session into the shareable `analysis=` value and returns `undefined` when everything is at its default, and `restoreAnalysis` reads one back. Both use the defaults the slices open at (`VOLCANO_DEFAULT`, `PATHWAY_FDR_DEFAULT`, `PATHWAY_SORT_DEFAULT`, `DB_DEFAULT_FILTER`). The shell supplies only what the session does not hold, the position's contrast beside the dataset's default contrast and the chart scale, so it never re-states a default. Pathway selection is never snapshotted, because a selected row is re-found in whatever data the link loads. The serialized field order is the public version-1 link format and is pinned by a test.
- **Cell navigator** (`src/explorer/CellNavigator.tsx`) — the explorer's track sidebar: category grouping, the search filter, and track selection. `matchesCellQuery` deliberately spans track id, marker-gene label and category, because users arrive with any of the three ("e9", "POMC", "GABAergic"). The grouping/filter/count derivations live WITH the markup that consumes them; in App they sat ~230 lines away from it.
- **Pathway-table seam** (`src/pathway-explorer/pathwayTable.ts`) — the single place a list of FGSEA rows becomes the page of rows a table renders: DB filter → search → sort → paginate, plus "drop the selection when it falls out of the filtered list". `usePathwayTable` is generic over the row type, because the single-track Pathway Explorer pages over `PathwayRecordWithDb` while the Compare view pages over its own per-population shape; all the seam requires is that a row can be identified — and **identity is `(db, pathway)`, never `pathway` alone**, since GO and Reactome both publish a "Glycolysis". A view's own extra filter arrives as an `include` predicate (the single-track FDR cutoff), so the seam never learns which statistic a view cuts on. `PATHWAY_SORTS` holds the standard orders as data: `nes` ranks by effect size, `pval` by adjusted significance, `rawpval` by the unadjusted p — three different questions, not interchangeable. Both views previously carried verbatim copies of all of this, including a shared defect: `useEffect(() => setPage(1), [])` — an empty dependency array under a comment promising a reset when the filters change, masked by the page clamp. The reset is real here, and `safePage` still clamps.
- **Bundle-writer seam** (`scripts/lib/bundleWriter.mts`) — the WRITE-side twin of `bundleLocators.ts`: the single place a builder's payload becomes bundle files. Derives every filename and window-global key from the registry `Dataset` value (never hand-spelled templates), owns wire slimming, the pathway-sibling shape (plain vs `{default, byContrast}`), the `pathways_index` name-union, and JSONP composition. Builder manifests are ASSERTION inputs, not derivations: the writer throws when a manifest's `trackId`, arm keys, or full contrast `{id, baseline, case}` bindings disagree with the registry, and preflights all output paths/keys for pairwise collisions and identifier validity. It takes **every track of a study at once** (the list must contain the registry `defaultTrack`) and owns the merged study files: `meta.js` (tracks in the given order; `groupN` from the default track's design cells), `qc_global.js` and one `pathways_index` over every track's pathway blocks. It also **derives** what it can from the payloads instead of trusting builders: arm counts and `is3v3` from `groupSamples` over the arm keys (a stated value must agree), and `deSummary[].nSig` by one rule, `countFdrSignificant` (finite `FDR < NSIG_FDR_THRESHOLD` = 0.05 in the default-contrast table; a null FDR does not count), which is the rule the QC table's "Sig (FDR<0.05)" heading states and the app's significance call elsewhere. Builders on the shared staged pipeline (`buildIntakeStudies(hooks)` in `scripts/lib/intakeStudies.mts`: stage every study, then publish or `--check`, value-compared registry sidecar, `--only`) state only their inputs; the September 5 intake builds through it. The HFD and OXT/AVP intake builders still call the writer per track and are left byte-identical because their source bytes are fingerprinted by their intake audits; moving them is a reviewed evidence change. Like the builders it replaced, it does not delete stale files (an offline-checker concern). The writer↔reader contract is pinned by a round-trip test (`bundleWriter.test.ts`) instead of prose alone.
- **Bundle-reader seam** (`scripts/lib/bundleReader.mts`) — the Node READ twin of the bundle-writer seam and of the browser loaders: the single place a script turns published bundles back into values. Two layers. `readJsonp(file, expectedGlobal)` parses without evaluating, refuses any other assigned global (a bundle in the wrong folder is not read as the wrong study) and any code around the JSON payload; `datasetBundlePaths(dataset)` names every bundle through `bundleLocators.ts`, so no script hand-spells `track_<id>.js`; `listDiskCorpus()` is the one sweep of `public/datasets` — registered datasets with a directory (in directory-name order), registered ones that are absent, and directories the registry does not name, which are **reported and never read** (no locator names their files or globals; each caller decides whether that is an error). Producers and audits that round-trip published bytes use only this layer: the query index, the bundle optimizer (which parses and rewrites under the locator's global, keeping the header via `jsonpHeader`; it never evaluates a bundle), the expression index, the upload guards and the deploy verifier. `readDatasetFromDisk(dataset)` is the dataset **as the browser shows it**: reviewed display corrections on the metadata (`reviewedMetadata`, as `loadDatasetMeta` applies them), the registry's unit winning over the bundle's (`resolveExpressionUnit`, shared with `buildPopData`), `isLowPower`, and the strict `rawTrack.ts` contrast rules for DE tables and pathway siblings. A script that publishes what the site shows reads through it and restates none of those rules — the agent export and the static `/studies/` pages (`seoPages.test.ts` pins every rendered track label to it); `bundleReaderParity.test.ts` pins its labels to the browser loader's.
- **Query-index corpus read** (`scripts/lib/queryIndexCorpus.mts`) — `build_query_index.mts`'s READ of the corpus, on the bundle-reader seam: `openQueryCorpus()` walks `listDiskCorpus` and yields each readable dataset's raw `meta.js` and then its declared tracks with their pathway siblings, one track at a time; `track(ds, id)` re-opens one for the expression pass. Its only policy is what an unusable bundle means, decided on `BundleReadError.reason` (`indexSkipReason`): missing or malformed (including a payload that is not a track's shape, and a broken pathway sibling) skips the track and feeds the builder's no-partial-index guard; wrong-global throws, `--allow-partial` or not. The read is raw — the manifest carries published labels and the client applies reviewed corrections — so index bytes stay a function of the published bundles. `queryIndexCorpus.test.ts` drives it over a damaged temp corpus.
- **Study publication record** (`scripts/lib/studyRecord.mts`; leaf `scripts/lib/html.mts`) — the build-time counterpart of the library's study record (`src/common/StudyMetadata.tsx`), for the pages and files published without the app: the single place a build script answers "which verified paper describes this dataset, which repository record does it link, which comparison does it headline and how many samples does each track have in it". `studyRecord(dataset, studySources, meta?)` is pure: the caller passes `data/seo/studySources.json` and the dataset meta as values, so either meta reader works. It returns the snapshot entry (by id, else accession), a publication that is `verified` or an explicit `none`, the PMID and DOI to link, the https repository URL, the default contrast (`getActiveContrast`) with its `groupLabels`, and per-track arm counts through the arm-count seam's tiers (`groupN` counts the default track only; another track's QC pair counts only when the default track shows it names the default contrast's arms; else null, rendered '–'). ONE identity rule: a titled snapshot whose PMID equals the registry's (field or citation), or is the source record's only linked PMID when the registry names none, or whose DOI equals the registry's (two empty DOIs never match); PMIDs compare by digits and DOIs as the tracker normalizes them. The study pages (`seoPages`, `seoStudyContent`), the citation guide (`seoGuides`) and the agent export render from it and restate none of it; `studyRecord.test.ts` pins the rule, and the renderer tests cover layout. `html.mts`'s `escapeHtml` is the one HTML escaper for those pages; it imports nothing, so `seoGuides` still avoids importing the page renderer.
- **Bulk-study constructor** (`defineBulkStudy` in `src/data/datasets.ts`) — the registry factory's second, narrower form: a single-track, single-default-contrast, two-arm public-expression study states only what differs (id, facets, citation, track, arm labels, contrast id); the constructor supplies the standard arm palette (`BASELINE_COLOR`/`CASE_COLOR`, named once), the lone default contrast, feature/pathway defaults, and derives `timeSeries.tracks` from the entry's own track. The macaque atlas and GSE135639 stay on `defineDataset` because they do not fit that shape. The fully-resolved registry is pinned by a committed golden (`datasetsRegistry.test.ts` + snapshot): a failure there means fix the entry, NEVER regenerate the snapshot.
- **Index-freshness seam** (`src/data/indexFreshness.ts`) — the single place "does this query-index manifest describe this registry" is answered. Consumers declare the facts they depend on (`coverage`, `trackCounts`, `defaultTrack`, `contrast`, `exprScaffold`); predicates live once; an UNVERIFIABLE need fails and the caller degrades to the slow-but-right per-track path (per-card for the library, all-or-nothing for reports — policy stays with the caller). The per-track fallback itself follows the contract rule in both directions: a non-default contrast is served only from its explicit `deByContrast`/`byContrast` block, while the registered default's table is `de`/the sibling's `default` block (the committed GSE135639 shape); a bundle predating a registry default swap is the manifest check's problem, not the reader's. `pnpm exec tsx scripts/check_datasets.mts` runs the same closure offline (locator-named files, manifest at full strictness, tracker sidecars bidirectionally against the documented accession alias sets, arm coverage; default tracks only — pass `--all-tracks` to parse every track) — read-only, and structural: value-level closure stays `build_query_index.mts --check`.
- **Query-wire module** (`src/data/queryWire.ts`) — the single place the query index's wire format is spelled: shard counts, the FNV-1a key hash and `indexKey` (uppercase), every file path and JSONP global (`MANIFEST_FILE`/`MANIFEST_GLOBAL`, `geneShardFile`/`geneShardGlobal` and the pathway, expression, name-union, card and track-pathways equivalents), the `ShardEnvelope` `{b, d}`, the manifest and browse-summary shapes, and every positional row layout behind an `encode…Row`/`decode…Row` pair (gene, pathway, expression — whose `sym` is omitted exactly when it equals its key — and track-pathway). `scripts/build_query_index.mts` is its write adapter and `src/data/queryIndex.ts` its read adapter; neither declares a wire shape or name of its own. Reader types keep post-v2 fields optional (a reader tests for the field it needs); `BuiltQueryManifest`/`BuiltDatasetSummary` are what the current generator writes. `trackEntry` precomputes a manifest track's `lowPower` with `src/utils/qcFlags`'s rule, never a copy. Encoders only order fields — rounding and the significance-safe `prob()` stay generator policy. DOM-free and registry-free because the Node builder imports it; its names and layouts are published URLs and bytes, so `queryWire.test.ts` pins them and proves the client reads where the writer writes.
- **Arm-count + arm-pill seam** (`contrastArmCounts` in `src/data/contrasts.ts`; `ArmPills`/`ArmVariesBadge` in `src/common/StudyMetadata.tsx`) — the single derivation of "how many replicates in this arm" for the ACTIVE contrast (tiers: loaded membership ∩ QC-kept, `groupN`, loaded QC, meta `qcFlags`; null renders '–'), sharing its per-arm tier helper with `defaultArmCounts` (which stays independent — its caller supplies the pooled pair). ArmPills is the ONLY spelling of the replicate pill (sm/md/lg + the countless `design` variant); no view hand-rolls a pill, a wash alpha, or an "n varies" badge.
- **QC table specs** (`src/qc/qcTables.ts`) — QCTab's six row/column derivations as pure, React-free spec builders over TYPED `QcGlobal`/`DatasetMeta` (the `as QcRow` any-wall is gone); `qcVocabulary` owns the de-macaqued arm labels and the legacy normal/obese fallback, building on `groupLabels`. QCTab injects JSX renderers per column key and renders the specs; the generic sortable-table chrome lives in `src/common/SortableTable.tsx`.
- **Track-column module** (`src/data/trackColumns.ts`) — the single place a track a view has asked for moves through its load lifecycle: `loading → ready | failed | unknown-track`, with error text, a per-column `retry` (from any state, so a failed pathway sibling is re-asked) and `pathwaysSettled`. popData is a render-time read (`popDataFor` at the request's CURRENT contrast), never stored, so a contrast switch reloads nothing and a hydrated sibling needs no re-read message. Both policies are required arguments: `pathways` (`include` / `omit`) and `trackList` (`verify` reads meta.js and is the only source of `unknown-track`; `trust` is for ids taken from the dataset's own track list or index rows). Kept columns never reload. Compare, the compare set (through the thin `useCompareSetColumns` adapter) and both report previews go through it; it sits on the track-data seam and deliberately NOT under the explorer store, whose cache, seed and overlay belong to the main explorer. It replaced the store's quiet path for Compare, whose catch swallowed a failed bundle into an endless "Loading X…".
- **Expression-survey derivation + load** (`src/expression-survey/expressionSurvey.ts`; `src/expression-survey/useSurveyLoad.ts`) — the survey view renders; these two modules decide. `expressionSurvey.ts` is pure: `selectSources` turns the filters into the regions, population choices and selected sources (the SFO boundary, AgRP and tissue-preparation rules live here), `surveyPanel` gives one result panel its ranked rows, bar axis, per-probe matrix cells (a probe-level source is split, never merged), the "Matched X → Y" note and the empty state, and `surveyExport` writes the samples/cohort-means CSV and the values + metadata JSON with the survey's own CSV escaping. **Reference eligibility is applied once** (`inReferenceScope`; an item without an explicit `referenceEligible: true`, such as an external atlas sample, is never eligible) and **value status has one vocabulary**: the `ValueStatus` code is what an export writes and `VALUE_STATUS_LABEL` is what the detail table shows. `useSurveyLoad` owns the value requests for an **expression source** selection: the shared four-request queue (work queued for a superseded survey is skipped; shared in-flight loads finish and warm the loaders' caches), per-source errors and a **per-source retry**. `useKeyedLoad` is the one cancelled-flag lifecycle for the catalog, validation reports and sample metadata, each with its own retry — so retrying one failed source no longer re-fetches the catalog, the atlas errors or the validation reports, as the view's single shared reload token did.
- **Export-provenance seam** (`src/utils/exportProvenance.ts`) — the single place an export says what it is evidence of. A view supplies a kind, its own settings and a subject (`trackSubject`, `timeSeriesSubject`, `columnsSubject`, or `localExportProvenance` for imported data); a HypoMap atlas file supplies an `AtlasSubject` to `atlasExportProvenance` instead, and its CSV columns name the atlas release tag and manifest SHA-256; the module owns the filename identity (`exportName`: dataset, track, contrast(s), kind — so two contrasts never save over each other), the snapshot (release, dataset, accession, contrasts and direction, unit, retained evidence, groups, settings, source link, reuse), the Metadata sheet (`metadataSheet`) and the CSV columns (`provenanceColumns`). Absences stay explicit: a missing contrast is `unresolved-contrast`, a time course says "Not applicable", an atlas file says it has no registered dataset, contrast or retained evidence, and a local dataset says it has no release, evidence or licence — except a local copy of PUBLIC results (`public:<dataset>:<track>:<contrast>`), which names the study it was copied from and says its release and evidence were not retained with the copy; a copy the user has added their own files to says it is mixed, so imported rows are never attributed to the public study. Sits beside the workbook and export-action seams; no view hand-names a file or writes its own settings sheet.
- **HypoMap atlas client** (`src/search/hypomap/atlas.ts`) — the single place the static HypoMap export (installed by `scripts/lib/hypomapAtlas.mts` under the tag `hypomap-release.json` pins) becomes values. It owns the transport (fetch of release-tag paths, swappable via `_setAtlasTransport` — an in-memory map in tests — with `_resetAtlasCache`), SHA-256 verification against the pinned manifest, gzip, the cohort check (`COHORT`: 384,925 cells, 18 datasets), symbol resolution (current symbol, then alias; a symbol that also names a feature outside the export is ambiguous; `missMessage` is the one wording both cards show), named gene records (`gene.id` / `gene.symbol`; the positions survive only for the co-detection client's reads), the region vocabulary and unit (`WHOLE`, `NO_REGION`, `EXPRESSION_UNIT`), pooled and per-dataset metrics per scope (`pooled`, `byDataset`; an absent feature is unavailable, never zero), the dataset mean and SEM (`datasetSummary`) and the CSV tables (`spatialTable`, `datasetTable`, `atlasTable` for co-detection's `comparisonCsv`; only a table carrying mean expression records `EXPRESSION_UNIT`, and a table of counts or percentages records the unit as not applicable). `loadAtlasGene` keeps one load per symbol, so the gene page's two HypoMap cards resolve a gene once and a failed load is forgotten for Retry; `findAtlasGene` resolves through the search index alone (the partner lookup). Each table carries an `AtlasSubject`, so `CsvDialog` downloads through the export-provenance seam like every other export.
- **Co-detection client** (`src/search/hypomap/codetection.ts`) — the single place the gated co-expression card talks to the loopback HypoMap service. `loadRanking(atlas)` and `loadComparison(atlas, partner, datasets)` own the transport (`/hypomap-preview-api/`, proxied to the service's `/api/`), response validation, gene-position resolution against the static export's search index, and the pooling checks (each total re-derived from its counts; the pooled total and C7 populations must equal the sum of the measured datasets). They return discriminated unions: a comparison is `ready`, `partial` (some selected datasets do not measure both genes — they stay listed with each gene's feature state, out of the pool) or `unsupported` (none do — never a "0 eligible cells" result); a response whose `source_export_manifest_sha256` or cohort disagrees with the static export, or that breaks the contract, is `rejected` with a message to show (fail closed, no numbers), while a transport failure rejects so the view offers Retry. `comparisonCsv` builds the rows handed to `CsvDialog`, keeping unsupported datasets as marked rows with empty values. `useLoad` (same directory) is the HypoMap views' one keyed load/retry lifecycle. `services/hypomap/codetection_wire.json` pins the wire on both sides: the Python test serves its index over HTTP and requires the golden responses, and the vitest tests feed the same responses to the client.
- **Gene selection** (`src/explorer/geneVocabulary.ts`; `src/common/GenePicker.tsx`) — the single place a picked name becomes a selected gene. A **vocabulary** is one track's symbols, the union of a dataset's loaded populations, or a case-folded union across studies; it owns the case policy (`keyOf`: exact, then the stored spelling case-insensitively, as `resolveGeneList` does; upper-case across studies so POMC and Pomc are one gene), the shared nomenclature authority (null when species are mixed, so redirects fail closed) and per-chip nomenclature facts read per source in that source's own namespace — the dataset's stored-symbol authority (`nomenclatureAuthorityForStoredDatasetSymbols`), and none at all for a source without one, so no chip borrows a namespace its study never used. `useBoundGeneSelection` routes `add` / `addMany` / `replace` through it over a `useGeneSelection` instance, whose state and resets stay in the explorer session. `GenePicker` is the one picker view (search, gene-list tools, count, Clear all, chips with the "now X" note) in the Gene Explorer, Compare tab and compare set.
- **Gene-list seam** (`src/utils/geneListFile.ts`; `src/common/GeneListTools.tsx`) — the single place a FILE becomes a list of symbols and a selection becomes a file. `parseGeneListFile` / `parseGeneListText` detect the shape from the extension (workbooks go to the lazily-loaded xlsx, GMT has a fixed field order) and otherwise from the content: the delimiter that runs through most lines (none → whitespace, which is what makes a pasted `POMC AGRP NPY` work), the gene column by a recognised header (`GENE_HEADER`: Gene, Symbol, gene_name, GeneID, …) or, headerless, by which column's cells look like symbols; `#` comments, blank cells and R's `NA` are dropped, and a one-line paste is a list rather than a one-row table. `resolveGeneList` then maps the file's names onto the DATASET's own spelling — case-insensitively, then through the alias index exactly as `GeneSearchBox` does for one gene — and reports `found` / `redirected` / `missing` / `ambiguous` (an alias shared by several stored genes fails closed) so a list dropped on the wrong species says which names it could not place instead of silently selecting fewer. `saveGeneList` writes txt (one symbol per line), csv or xlsx through the export-action, CSV and workbook seams. `LoadGeneListButton` and `SaveGeneListMenu` sit in the shared `GenePicker` (gene selection, below) in the Gene Explorer, Compare tab and compare set; `SaveGeneListMenu` alone serves the volcano's threshold-passing list, whose rows carry direction, log2FC, p and FDR.
