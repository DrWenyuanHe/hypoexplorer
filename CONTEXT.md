# CONTEXT

Domain + architecture vocabulary for HypoExplorer. Use these terms exactly in
code, comments, and reviews so language stays consistent. Data shapes live in
[docs/DATASET_CONTRACT.md](docs/DATASET_CONTRACT.md); this file names the concepts.

Each architecture entry names the module that owns a responsibility and the rule
nobody else may break. The module's own header comment, its types and its tests
are the source of truth for its API; read them for exports, fields and signatures.

## Domain

- **Dataset** — one study/modality (macaque snRNA, mouse bulk HFD, miRNA array…). Registered in `src/data/datasets.ts`.
- **Study selection** — the studies included in a cross-dataset analysis after its capability, evidence, sample-count, category and individual-study restrictions. No individual restriction means all eligible studies; an explicitly empty individual selection means no studies.
- **Track** — the unit a user selects within a dataset: a cell population for single-cell, a whole-tissue track for bulk/miRNA.
- **Group** — an experimental arm `{ key, label, color }` (Normal, Obese, Chow, HFD…).
- **Contrast** — a baseline→case comparison between two groups; carries the DE table and (when supported) the pathway table.
- **Significance tier** — a result's standing against the app's fixed cutoffs: `fdr` (passes FDR < 0.05, a discovery), `nominal` (raw p < 0.05 but not FDR, uncorrected and labelled "p < 0.05 only") or `none`. A fact about the result, so its label never depends on the listing mode. _Avoid_: "significant" for the nominal tier.
- **Listing mode** — the reader's choice of what a cross-study view leads with: FDR results alone, or FDR results followed by the nominal tier. It changes what leads, the order and what is counted, never a row's tier.
- **Cross-study listing** — one term's results across a study selection, arranged for a listing mode: the rows that lead, the rest in order, and the track and dataset counts. Search summaries, the gene report and the pathway report all present a cross-study listing; each decides only how much of it to show and what starts folded. A dataset that was selected but has no measured result still counts toward the selection, not toward the listing.
- **Explorer tab scope** — what an explorer tab's content follows. **Track-scoped** tabs (Gene Explorer, Pathway Explorer, Circadian) redraw for the selected track; the **dataset-scoped** tab (Quality Control) describes every track of the study at once, so selecting a track while one is showing is a request to see that track.
- **Compare** — the explorer's across-tracks view of one dataset. It is not a track and carries no tab; it remembers the track and tab it was entered from and returns there when left.
- **Feature** — the row entity: a gene (default) or a miRNA. Stored under the `gene` key; `featureType`/`featureLabel` drive the UI label.
- **Ambiguous authority match** — the nomenclature status for a stored name whose active authority candidates remain unresolved. No single authority identifier or canonical alias target is implied. This qualifies identifier interpretation; it does not change measured expression or establish the study's organism.
- **Rename group** (`src/data/symbolRenames.ts`; built into `public/nomenclature/renames.js` by `scripts/build_search_names.mts`) — one authority's current symbol plus the retired symbols the corpus still stores for the same record (Fam237b and Gm8773 under MGI). A retired symbol joins only as a single-target `previous` row, or a single-target `alias` row that is a locus placeholder, with the current row's authority ID and first-letter case. A study is read under another member only in its own stored-symbol authority, and `pickStoredMember` is the one rule for which row answers: the queried symbol's own row, else the one stored partner, else the current symbol, else none. The cross-dataset gene query (both paths, marking `TrackRow.storedAs`), the expression preview, `resolveGeneCI` / `compareCell` (given the table) and the search names all read it.
- **Expression source** — a preparation, measurement scale and set of sample groups used for a descriptive expression survey. It may come from a registered track or stand alone as an expression-only reference; it does not imply a DE contrast.
- **Expression profile** — one measured cell, library, tissue sample or pool in an expression source. Its count describes measured profiles; independent biological replication depends on the source's animal, donor, litter or pool design.
- **Reference eligibility** — an explicit source-condition decision for the survey's eligible-reference filter. Unknown feeding state or an excluded intervention does not become eligible because a source is called a reference or its values pass an import check.
- **Current pathway provenance** — evidence that current enrichment outputs belong to the declared analysis and inputs. It is distinct from a comparison to a historical migration baseline and from agreement with author-reported pathways.
- **Retained input identity** — an expected input fingerprint preserved from fixed earlier evidence. It identifies the intended source but does not establish that the input is currently available or has been read and verified again.
- **popData** — the transformed, React-friendly view of one track (built by `src/data/buildPopData.ts`): `de`, `cpm`, `volcanoPts`, `allPathways`, resolved `contrast`, `groupSamples`, `sampleOrder`, `expressionUnit`.
- **Bundle** — a generated `.js` data file under `public/datasets/<id>/` (or `public/query/`, `public/nomenclature/`) that sets exactly one namespaced `window` global as a side effect. Loaded by `<script>` injection, not `fetch`: bundles are served cross-origin from R2 with no CORS policy. A track's FGSEA pathways ship in a **sibling bundle** (`track_<id>.pathways.js`) so the gene path never downloads them.

## Architecture

- **Sample-value seam** (`src/utils/sampleValues.ts`) — the only place a contrast's groups are resolved to sample positions in the `cpm` array and values are read from there. No code outside it slices `cpm` by position. Every spelling of the expression unit (export column headers and on-screen labels) and of the group-label fallback (`groupLabels`: the contrast's own labels, else neutral Baseline/Case, never macaque Normal/Obese) comes from here, so CSV, XLSX and charts cannot disagree and an unknown unit is never mislabelled CPM.
- **Workbook seam** (`src/utils/workbook.ts`) — the only place sheet rows become a downloaded `.xlsx` on the main thread; shared sheet row shapes live in `src/utils/excelExport.ts`. One deliberate exception: the circadian workbook (`src/circadian/circadianWorkbook.ts`) assembles its own sheets because it is built incrementally in a Web Worker, which `writeWorkbook` cannot do. No component calls `XLSX.utils` directly.
- **Export-action seam** (`src/utils/exportAction.ts`) — the workbook seam owns what an export writes; this owns what an export click does: the one busy-state policy, the one filename sanitizer and the one `<a download>` transport. No component hand-rolls a spinner timer or a filename scrub.
- **CSV seam** (`src/utils/csv.ts`) — the only place a table becomes a downloaded `.csv`. It owns the byte policy (BOM, CRLF, minimal quoting), the spreadsheet formula guard, and placing the export-provenance columns after the caller's own. No view escapes a cell or joins a line. Exception: the expression survey still writes its own always-quoted CSV.
- **Dataset-meta value** (`src/data/datasetMeta.ts`) — the active dataset's `DatasetMeta` is a value passed down from App as props. There is no `window.POP_META` and no module-level "active dataset"; a null meta degrades to bare ids, never to a stale previous dataset. Consumers get tracks through a `getTrack(trackId)` closure and never learn the store's cache key.
- **Registry factory** (`defineDataset` in `src/data/datasets.ts`) — derives the file and window-global locators from `id` and the bundle base URL from `BUNDLE_BASE`, so an entry states only what differs. `category` is required and typed against `src/data/datasetCategories.ts`; an unknown id throws rather than mis-stratifying. `datasets.ts` is the manifest and registry lookups only: contrast resolution lives in `src/data/contrasts.ts` and URL/global-key locators in `src/data/bundleLocators.ts`, both pure functions of a `Dataset` value.
- **Author-validation sidecar** (`data/author-validation/validation-records.generated.json`; adapter `src/data/authorValidation.ts`) — the registry-keyed ledger that keeps three claims separate: the pipeline trace (public rows trace to the registered analysis output, which the data release restores rather than this repository), the processed-source match (the input matches the author's deposited processed data) and the author-result match (a direct comparison with the author's own result table). Weaker evidence or missing access is never rendered as a pass. The sidecar covers exactly the registry and ships in the app bundle. `build_author_validation.mts --require-complete` joins the evidence layers with `manual-review.json` and fails while any in-scope audit is still in progress.
- **Study-selection module** (`src/crossdataset/studySelection.ts`; value and URL form `src/crossdataset/studySelectionLink.ts`; view `src/crossdataset/StudySelectionPanel.tsx`) — the only place a report's **study selection** is held, derived and written to the URL, per report kind (`gene` / `pathway`). The router stores one selection per kind. Invariants: an explicitly empty individual selection never widens, even when a link's studies have all left the registry; with a minimum sample count set, the report waits for measured counts and a study with an unknown arm count fails the filter, so a temporarily broader cohort is never queried or shown; the snapshot's field order is the public version-1 link format; the router imports only `studySelectionLink.ts`, and `lazyChunkBoundaries.test.ts` fails if the entry bundle reaches either evidence ledger. `StudySelectionPanel` is the one "Study filters" disclosure both reports render.
- **Page shell + report primitives** — `src/common/PageShell.tsx` owns the full-page chrome (accent strip, sticky header, logo, breadcrumbs) for the gene and pathway reports and the reference pages; the explorer shell, hub and tracker keep their own chrome. `src/crossdataset/forestReport.tsx` holds only what the report pages genuinely share (axis scaling, the forest dot's chart fill `directionFill`, contrast labels read from the resolved contrast, category grouping, filter chips, the load lifecycle `useReportQuery`) and is deliberately not one all-owning report component. The pathway report keeps its own forest row. Both reports run their load lifecycle through `useReportQuery`; none hand-writes it.
- **Bundle-source seam** (`src/data/bundleSource.ts`) — the only place a bundle URL and window-global name become a value: `<script>` injection, the one URL-keyed cache, in-flight dedup and the cache-bust. Required and optional loads are separate entry points so the failure policy is part of the request: they share one transport request per URL but keep separate promises and failure handling. A failed load stays retryable, because a script error cannot tell a 404 from a network blip; the one cached absence is an optional load whose script ran without defining its global. `peekGlobalBundle` is the one way to read an eager global off `window`. `BUNDLE_BASE` (`src/data/bundleBase.ts`) is DOM-free because Node scripts type-check the registry. `/tracker/catalog.js` is deliberately origin-relative: the off-origin build prunes only the trees served from R2 (`vite.config.ts`, `drop-off-origin-data`).
- **Expression-source reader** (`src/expression-survey/sourceJson.ts`) — the single transport for the survey's release-local JSON (NeuroSeq, the OXT reference, GTEx/HPA/Allen). It owns the per-family file allow-list, the cache-bust, one session cache and forget-on-failure; each family's loader keeps its own validation. The gene page's NeuroSeq teaser is a projection of the survey's own per-population results, so the two cannot disagree. The HypoMap atlas client keeps its own transport.
- **Track-data seam** (`src/data/trackData.ts`) — the only place a (dataset, trackId) becomes a loaded track and a loaded track becomes popData. The pathway policy is a required argument, so a pathway-less view is a stated choice. `popDataFor` requires dataset and contrast: when they were optional the transform silently fell back to the macaque atlas. When a pathway sibling arrives, hydration invalidates every contrast's cached transform for that track, not just the visible one; otherwise switching contrasts could keep showing an empty pathway table. Everything that needs popData goes through this seam.
- **Explorer store** (`src/data/explorerStore.ts`) — the only place the main explorer's per-dataset resources (meta, QC, loaded tracks) are loaded and held, and the only place a late resolve is dropped (the stale-write guard is written once). Navigation stays the shell's; the store takes what is active as input. It serves the main explorer alone; Compare, the compare set and report previews load through the track-column module.
- **App router** (`src/appRouter.ts`) — the only place that answers "where is the user, and how do they get somewhere else": the `AppView` union, each view's parameters, every navigation verb and the URL as a two-way binding. It drives the route-landing module (below), which decides what an untrusted route means. The router runs one **navigation attempt** at a time: every URL event, router verb and user-originated change starts one and retires the attempt in flight, so a link still landing never overrides a later click, search or Home. Each attempt carries a write policy: `replace` for a followed URL (Back never lands on a raw link that re-pushes itself), `push` for a user action, `hold` after an `ignore` landing so an in-page anchor stays put. View-reported setters start an attempt only on a real change, so a view echoing its mount props cannot cancel a landing; shell controls call `supersede()` before `navigate`. The router decides where; the shell's explorer position decides how a navigation intent lands, which keeps the router free of shell state. `navigationAttempts.test.tsx` pins supersession, in-place canonicalization and anchor preservation.
- **Route landing** (`src/routeLanding.ts`) — the only reader of a route, at boot and for every later URL. It is pure (no React, `window` or network) and returns a **landing**: `ignore`, `stay`, `refuse` (one of the `RouteRefusal`s; applies nothing, and App renders the error page), `page`, `explorer` or `verify`. A URL destination is absolute: an explorer route that names no track, an unknown track, or Compare on a dataset with fewer than two populations lands on the default track, so the same link always lands in the same place, while a saved analysis refuses rather than land somewhere it did not name. "Keep the current track" belongs only to the in-app `openInExplorer(id)` verb, which reads no URL. `applyPage` is the one page transition for boot, URL landings and page verbs. `routeLanding.test.ts` pins the rules as a table; `routeLandingRegressions.test.tsx` pins the boot and Back/Forward cases.
- **Explorer position** (`src/explorer/explorerPosition.ts`) — the only place the explorer's dataset, track-or-Compare, contrast and tab are held and moved. Callers send a **navigation intent**; `nextPosition` returns the next position plus the session reset scope and the track to load. The tab rule is stated once here. Track ids are trusted; the untrusted-URL check stays in the router.
- **Explorer session** (`src/explorer/explorerSession.ts`) — the only place the explorer's selected and configured state is held, reset (`RESET_MATRIX`) and written to the shareable `analysis=` snapshot. The snapshot's field order is the public version-1 link format, pinned by a test. Pathway selection is never snapshotted.
- **Cell navigator** (`src/explorer/CellNavigator.tsx`) — the explorer's track sidebar. Its search deliberately matches track id, marker-gene label and category, because users arrive with any of the three ("e9", "POMC", "GABAergic").
- **Pathway-table seam** (`src/pathway-explorer/pathwayTable.ts`) — the only place a list of FGSEA rows becomes a rendered page of rows (filter, search, sort, paginate, drop a selection that falls out). Pathway identity is `(db, pathway)`, never the name alone, since several databases publish the same name. A view's own filter arrives as a predicate, so the seam never learns which statistic a view cuts on.
- **Bundle-writer seam** (`scripts/lib/bundleWriter.mts`) — the write-side twin of `bundleLocators.ts` and the only place a builder's payload becomes bundle files. Filenames and globals come from the registry; builder manifests are assertions the writer checks against the registry, not inputs it trusts. It takes every track of a study at once and derives arm counts and `deSummary[].nSig` (FDR < 0.05 in the default contrast) itself. The HFD and OXT/AVP builders still call it per track and stay byte-identical because their intake audits fingerprint them. `bundleWriter.test.ts` pins the writer↔reader round trip.
- **Bundle-reader seam** (`scripts/lib/bundleReader.mts`) — the Node read twin of the writer and of the browser loaders: the only place a script turns published bundles back into values. It parses JSONP without evaluating it and refuses a wrong global; directories the registry does not name are reported, never read. `readDatasetFromDisk` returns a dataset as the browser shows it (reviewed metadata corrections, the registry's unit, strict contrast rules), so scripts that publish what the site shows restate none of those rules. `bundleReaderParity.test.ts` pins its labels to the browser loader's.
- **Query-index corpus read** (`scripts/lib/queryIndexCorpus.mts`) — the query-index builder's read of the corpus, on the bundle-reader seam. Its only policy is what an unusable bundle means: missing or malformed skips the track and feeds the no-partial-index guard; a wrong global always throws. The read is raw, so index bytes are a function of the published bundles.
- **Study publication record** (`scripts/lib/studyRecord.mts`) — the build-time counterpart of the library's study record, and the only place a build script decides which verified paper describes a dataset, which repository record it links, which comparison it headlines and its per-track sample counts. It applies one paper-identity rule (pinned by `studyRecord.test.ts`). The static study pages, the citation guide and the agent export render from it and restate none of it.
- **Bulk-study constructor** (`defineBulkStudy` in `src/data/datasets.ts`) — the registry factory's narrower form for single-track, two-arm public-expression studies. The fully resolved registry is pinned by a committed golden (`datasetsRegistry.test.ts`): a failure during a refactor means fix the entry, never regenerate the snapshot. A deliberate manifest change (a new dataset, a corrected label) regenerates it in the same commit and says so.
- **Index-freshness seam** (`src/data/indexFreshness.ts`) — the only place "does this query-index manifest describe this registry" is answered. Consumers declare the facts they depend on; an unverifiable need fails and the caller degrades to the slow per-track path. A non-default contrast is served only from its explicit by-contrast block. `scripts/check_datasets.mts` runs the same closure offline.
- **Query-wire module** (`src/data/queryWire.ts`) — the only place the query index's wire format is spelled (file names, globals, hashing, row layouts). `scripts/build_query_index.mts` writes through it and `src/data/queryIndex.ts` reads through it; neither declares a shape of its own. Its names and layouts are published URLs and bytes, so `queryWire.test.ts` pins them.
- **Data-origin layout** (`src/data/dataOriginLayout.ts`) — the only statement of what the data origin (the R2 bucket) holds: its trees, the two mutable pointers and their build-id formats, the prefixes of one query generation, and per-key cache, content-type and WAF admission. The uploader, edge rules, deploy preparation and verification, `vite.config.ts` and `originHealth.ts` import it and none spells a pointer key or cache lifetime of its own. `scripts/lib/queryGeneration.mts` is the one pointer-then-manifest reader behind `prepare:deploy`, `fetch:query` and the uploader. `dataOriginLayout.test.ts` pins the invariants (every uploadable key is WAF-admitted; only pointers have the short TTL).
- **Arm-count + arm-pill seam** (`contrastArmCounts` in `src/data/contrasts.ts`; `ArmPills` in `src/common/StudyMetadata.tsx`) — the single derivation of "how many replicates in this arm" for the active contrast (unknown renders '–'), and the only spelling of the replicate pill. No view hand-rolls a pill or an "n varies" badge.
- **QC table specs** (`src/qc/qcTables.ts`) — QCTab's row and column derivations as pure spec builders over typed QC and meta; QCTab only renders them.
- **Track-column module** (`src/data/trackColumns.ts`) — the only place a track a view has asked for moves through its load lifecycle (`loading → ready | failed | unknown-track`, with per-column retry). popData is read at render time for the current contrast, never stored. Both policies are required: `pathways` (`include` / `omit`) and `trackList` (`verify` / `trust`). Compare, the compare set (through `useCompareSetColumns`) and both report previews use it; it deliberately does not sit under the explorer store.
- **Expression-survey derivation + load** (`src/expression-survey/expressionSurvey.ts`; `src/expression-survey/useSurveyLoad.ts`) — the survey view renders; these two modules decide. Reference eligibility is applied once (`inReferenceScope`: only an explicit `referenceEligible: true` qualifies), and value status has one vocabulary shared by exports and the detail table. `useSurveyLoad` owns the shared request queue, per-source errors and per-source retry.
- **Export-provenance seam** (`src/utils/exportProvenance.ts`; formatting in `src/utils/exportProvenanceFormat.ts`) — the only place an export says what it is evidence of. A view supplies a kind, its settings and a subject (a track, a time course, side-by-side columns, or a HypoMap atlas file); the module owns the filename identity (so two contrasts never save over each other), the provenance snapshot, the XLSX Metadata sheet and the CSV provenance columns. Absences stay explicit (an unresolved contrast, "Not applicable" for a time course, no registered dataset for an atlas file). No view hand-names a file or writes its own settings sheet.
- **HypoMap atlas client** (`src/search/hypomap/atlas.ts`) — the only place the static HypoMap export (pinned by `hypomap-release.json`, installed by `scripts/lib/hypomapAtlas.mts`) becomes values: transport, SHA-256 verification against the pinned manifest (the manifest always; a shard only when its bytes arrive still gzip-encoded, see `docs/agent-context/delivery.md`), the cohort check, symbol resolution, per-region and per-dataset metrics (an absent feature is unavailable, never zero) and the CSV tables. Each table carries an atlas subject, so downloads go through the export-provenance seam.
- **Co-detection client** (`src/search/hypomap/codetection.ts`) — the only place the gated co-expression card talks to the loopback HypoMap service. It re-derives and checks every pooled total, fails closed (`rejected`, no numbers) on a manifest, cohort or contract mismatch, and never reports "0 eligible cells" when no selected dataset measures both genes (`unsupported`). `services/hypomap/codetection_wire.json` pins the wire for both the Python and TypeScript tests.
- **Direction text + listing words** (`src/statistics/direction.ts`; `src/statistics/listingWords.ts`) — two leaf modules, each one rule several views must agree on. `directionTextColor` is the only colour for result text that states a direction: only the FDR tier is coloured, and only with the text tokens `resultTextContrast.test.tsx` holds to 4.5:1. The chart fills are for marks only. `listingWords.ts` owns the words that change with the **listing mode** ("significant" only in the FDR mode) and `nominalCaveat`, the multiple-testing family a nominal result was not corrected across. Headlines, verdicts, tallies and notes that depend on the order or on what is shown stay in the views: they need facts a listing does not record.
- **Gene selection** (`src/explorer/geneVocabulary.ts`; `src/common/GenePicker.tsx`) — the only place a picked name becomes a selected gene. A vocabulary owns the case policy (case-folded across studies so POMC and Pomc are one gene) and reads nomenclature facts in each source's own namespace; with mixed species, redirects fail closed. `GenePicker` is the one picker view, used in the Gene Explorer, Compare tab and compare set.
- **Gene-list seam** (`src/utils/geneListFile.ts`; `src/common/GeneListTools.tsx`) — the only place a file becomes a list of symbols and a selection becomes a file. `resolveGeneList` maps names onto the dataset's own spelling and reports found / redirected / missing / ambiguous, so a list dropped on the wrong species says which names it could not place instead of silently selecting fewer; an alias shared by several genes fails closed. The shared `GenePicker` opens `LoadGeneListDialog` and saves through `saveGeneList`; `SaveGeneListMenu` is the standalone save for a list that is not a selection (the study record's passing genes).
- **Compare cell** (`src/compare/compareCell.ts`) — the single answer to what one Compare column says about one gene: `unavailable` (nothing was read, so no view may say "not detected"), `not-detected` (no DE row under any casing, and no group values even if `cpm` carries the symbol) or `measured`. Every Compare chart, summary table and export row builder reads cells, so these rules are stated once; before, an unmeasured study could export a group mean of 0.
