# Project guidance

## Data provenance
The explorer's macaque data is an **obese-vs-normal re-analysis of Lei et al., *Cell Metab.* 2024;36(2):438–453.e6** ([doi:10.1016/j.cmet.2024.01.003](https://doi.org/10.1016/j.cmet.2024.01.003), PMID 38325338). Samples `HCA_Macaque001_S001–S006` (S001–003 Normal, S004–006 Obese); 60 populations. The source is credited on its library record and study page; software and reference citations are on How to cite (`src/acknowledgements/references.ts`).

## Project structure
The repository separates these concerns:
- **Online explorer** (committed, deployed): `src/`, `public/`, `index.html` → built to `dist/`. The React/Vite app "HypoExplorer", written in **TypeScript** (shared domain types in `src/data` flow from `src/types/`). It browses the datasets and thematic categories counted in the [generated context map](agent-context/generated/datasets.md), spanning the macaque snRNA atlas, bulk RNA-seq and microarray studies from supported mammalian, avian, and fish species, all registered in `src/data/datasets.ts`. Each dataset's bundles are written to `public/datasets/<id>/` from the analysis tables by the `scripts/build_*bundles*.mts` and `scripts/build_geo_datasets.mts` builders (run via `tsx`; some have `build:*` aliases in `package.json`, while `build_geo_datasets.mts` and `build_explorer_bundles_batch2.mts` are run directly with `pnpm exec tsx`) through the bundle writer in `scripts/lib/bundleWriter.mts`; the macaque atlas comes from `scripts/migrate_macaque_bundles.mts`. Only each dataset's `meta.js` is tracked here: the full bundles are served from the R2 data origin (published by `upload:bundles`), and `pnpm run fetch:data` restores a reduced public copy (no KEGG, no macaque per-animal CPM) that must never be uploaded. The query catalog (`public/query/`), the tracker catalog (`public/tracker/catalog.js`) and the reference atlases (`public/expression/{gtex,hpa,allen-human}/`) are gitignored too; `pnpm run fetch:query`, `pnpm run fetch:expression` or `pnpm run prepare:deploy` fetch them from the live origins. Gene alias/previous-symbol search and the `#/nomenclature` reference page read `public/nomenclature/` (committed), regenerated from the tracked `data/nomenclature/nomenclature.tsv` by `pnpm run build:nomenclature` — rerun it whenever a dataset joins the corpus. Then run `pnpm run build:search-names`, which derives the unified-search names (`names.js`) and the rename groups (`renames.js`) from that table; `tsx scripts/build_search_names.mts --check` fails when either is stale, and `npx tsx --test scripts/lib/searchNames.test.mts` covers its rules.
- **Expression survey**: a gene's survey lives on its gene page ("Where <gene> is expressed": one tile per source, each opening that source's survey); `#/expression` compares several genes and holds the population catalog and validation. Both render `GeneSurvey` (`src/expression-survey/GeneSurvey.tsx`). `src/expression-survey/expressionData.ts` dispatches existing-track expression, NeuroSeq and expression-only reference collections. Existing-track values use the lossless query index; NeuroSeq and the GSE147092 OXT reference use release-local JSON under `public/expression/`. The OXT reference preserves deposited CENSUS estimates and cell/animal-pool metadata without adding a DE registry entry. Read [the survey runbook](runbooks/EXPRESSION_SURVEY.md) and [the source import record](../data/expression/oxt-reference/README.md); `pnpm run check:expression-reference` checks every retained OXT value offline.
- **Analysis — not tracked here** (the explorer's source of truth): `data/raw/results/` (per-cluster edgeR DE + FGSEA CSVs that feed the macaque `public/datasets/macaque_snrna/` bundles), `data/raw/pseudobulk/` (the per-animal pseudobulk counts they were fitted from) and `geo_replication/datasets/` (the GEO replications, source for the other bundles) are held by the maintainer. `pnpm run fetch:data` restores their redistributable part from the pinned data release (`data-release.json`), with KEGG rows and withheld files removed. The code is tracked: `geo_replication/scripts/` (including the sealed `run_dataset.R`), `geo_replication/config/` and the producers under `scripts/` and `data/raw/scripts/`.
- **Edge — Cloudflare Workers** (committed): the site is an assets-only Worker (`wrangler.jsonc`, deployed with `pnpm run deploy:cf`), and the R2 data origin at `data.hypoexplorer.com` is served directly by its R2 custom domain. Cloudflare zone rules (edge cache, WAF rate limiting and method/path allow-lists) and a scheduled spend guard Worker bound its R2 read cost; see [edge protection](runbooks/EDGE_PROTECTION.md). The earlier data gate Worker was retired in 2026-10. The build also prerenders the public `/studies`, `/methods`, `/how-to-cite` and `/about` documents from `scripts/lib/seo*.mts`; they are real assets, so the service worker's navigation fallback (when `VITE_SERVICE_WORKER=1`; it is off by default on Cloudflare) is scoped to the root document only.
- **Writing — kept out of the repo**: manuscripts, drafts, slide decks and generated figures are not part of this repository.

See `.gitignore` for exact patterns. Keep `geo_replication/` out of the website app.

## Files not in this repository

This public repository tracks code, configuration, intake specifications and the top-level evidence ledgers (for example `data/internal-qc/assessments.generated.json` and the producers in `data/raw/scripts/`). It does not track:
- data inputs and analysis outputs (`data/raw/results/`, `data/raw/pseudobulk/`, `geo_replication/datasets/`) and the full dataset bundles;
- evidence subtrees (the folders under `data/internal-qc/`, and the source files behind dated `data/quality/` and `data/author-validation/` records);
- source downloads for the reference atlases under `data/expression/` (GTEx, HPA, Allen, NeuroSeq), and the HypoMap atlas H5AD and MGI reports under `data/hypomap/source/` (pinned in `data/hypomap/provenance.json`);
- the retained audit cache used to rebuild the evidence ledgers.

`pnpm run fetch:data` restores what the pinned hypoexplorer-data release holds. `data-release.json` names that release and lists its archives; one release can combine parts first published under different tags, so check that file rather than assuming a tag. `pnpm run fetch:query` and `pnpm run fetch:expression` fetch the query catalog and the built reference atlases from the live origins. Anything in none of those is held by the maintainer. A doc that cites such a path describes where the file lives in a full checkout, not a file you should expect here.

## Analysis environment
R 4.6.0 is the single analysis environment: edgeR 4.10.1, limma 3.68.4, fgsea 1.38.0, msigdbr 26.1.0 (MSigDB 2026.1.Hs), org.Mm.eg.db / org.Rn.eg.db 3.23.0 (Bioconductor 3.23). The original corpus's DE, SE, CPM and FGSEA tables were regenerated under it on 2026-09-25; the record, comparisons and reproduction commands are in [the regeneration README](../data/quality/regeneration-r460-2026-09-25/README.md). Later source-reviewed intakes retain separate provenance and replay records.
- **Producers.** Current bulk: `scripts/regenerate_bulk_de_current.R` runs the `scripts/regen-r460/*_r460.R` producers, routing GSE135007 to its persisted-matrix serialization successor. They share the duplicate-symbol, fractional-count and CPM rules in `scripts/lib/de_common.R`. `scripts/regenerate_bulk_de.R` retains the September regeneration route. Macaque: `data/raw/scripts/run_atlas_r460.R`. The producers they replace (`geo_replication/scripts/run_dataset.R`, `scripts/run_mouse_fgsea.R`, `data/raw/scripts/run_all_clusters.R` and the other originals) are pinned by retained evidence and stay byte-identical; do not edit them.
- **GSE135007 serialization successor.** `scripts/regen-r460/run_gse135007_serialized_r460.R` requires `HYPO_OUT_ROOT`, writes its canonical fractional count matrix with 17 significant decimal digits, checks an exact numeric roundtrip and fits the reread persisted matrix. Preserve the dated products and original replay review as history; the maintainer's serialization runbook covers source, adoption, current verification and the successor chain. `scripts/audit_september5_intake_current.mts` writes `data/intake/september5-2026/audit-current.generated.json`; `pnpm run check:intake` checks that current audit. The earlier intake audit and its producer remain historical evidence.
- **OXT/AVP intake.** `scripts/regen-r460/run_oxt_avp_r460.R` uses `data/intake/oxt-avp-2026-10-19/studies.json` and the shared log-expression/symbol rules. The admitted GSE65663 comparison uses five independent rat pools per arm and deposited median-baselined log2 RMA values, with no second log transform or raw-CEL refit. Its dedicated analyses/config, bundle builder and current source/model/output audit follow [the intake runbook](../data/intake/oxt-avp-2026-10-19/README.md). `pnpm run check:oxt-avp` checks its public products and audit; the exact R producer's `--check` additionally replays limma. Held GSE30733 is not registered by this intake.
- **Outputs.** Producers write LF text on every platform and record the SHA-256 of those bytes (`text_output_policy` in provenance). Raw-library CPM (`<stem>_CPM_raw.tsv.gz`, macaque `de/rawcpm.csv`) is written but git-ignored; the explorer publishes TMM CPM. Evidence that pinned replaced outputs is re-derived by successor producers and checks (`scripts/*_r460.*`, `scripts/build_internal_qc_r460.mts`, `scripts/regen-r460/`), never by editing the pinned ones.
- **Retained audit cache.** Rebuild evidence ledgers only on the computer that holds the retained audit cache (about 5.5 GB, held by the maintainer and not part of the public repository). On any other checkout, `build_internal_qc_r460.mts` reads less evidence and its result is weaker: datasets drop from pass to not assessed. The builder therefore refuses to write when the rebuild would lose a pass or report more unavailable inputs than the committed ledger. Pass `--accept-downgrade` only for a reviewed scientific change. On a second computer, commit code and source changes, record the ledger rebuild as pending in a GitHub issue, and rebuild the ledgers on the original computer. The maintainer's cache-recovery handoff (`data/quality/cache-recovery-2026-10-20/`, not in this repository) describes how to copy the cache to another computer.
- **Tests without the cache.** On a checkout without the cache, the tests listed in `src/__tests__/retainedAuditCache.ts` cannot assess their evidence: tests that expect `pass` fail, and tests that expect a rejection pass without reaching the check they name. This repository's GitHub Actions test step does not set `HYPOEXPLORER_RETAINED_CACHE`; the tests that read retained evidence or pre-publication history are excluded in `vite.config.ts` instead. With `HYPOEXPLORER_RETAINED_CACHE=absent`, `src/__tests__/setup.ts` skips a listed test only when every gitignored input it declares is missing, and reports each skip in the job log and step summary. If any declared input is present, the test runs and must pass. Without the variable, every listed test runs, and on the original computer they must all pass. A skipped test is not a result: before a ledger rebuild or release, run the full suite without the variable on the original computer. When a test starts or stops reading a retained input, update its entry in that file. `retainedAuditCache.test.ts` checks that every declared input is gitignored and untracked.
- **Session records.** These sit beside the analysis outputs, so they are not tracked here; `pnpm run fetch:data` restores them. Each bulk table has `<stem>_sessionInfo.txt` and `<stem>_provenance.tsv` beside it in `geo_replication/datasets/<dir>/processed/` (plus `_SE_` variants and `<stem>_FGSEA_provenance.tsv`). Each macaque population has `sessionInfo.txt`, `de/DE_provenance.tsv` and `fgsea/FGSEA_provenance.tsv` under `data/raw/results/<population>/`, and the run has `data/raw/results/_global/RUN_provenance.tsv`.
- **Upstream processing.** `geo_replication/config/upstream_processing.tsv` records each source accession's aligner, genome build and annotation; `pnpm run check:upstream` checks it.
- **R 4.4.1** stays installed only to re-verify sealed history recorded under it (`scripts/run_sealed_report_check.py`, and `scripts/run_historical_check.py` in the maintainer's repository). Do not produce new outputs with it. Sealed checks read the pre-regeneration bytes through the supersession manifest described in the regeneration README. The maintainer's `scripts/historical_native_runtime.py` (not in this repository) narrowly relocates three pinned historical R replays after checking the producer, R script, executable and declared package closure; follow the [native runtime runbook](runbooks/HISTORICAL_NATIVE_RUNTIME.md), where `HYPOEXPLORER_NATIVE_RUNTIME_ROOT` selects a verified local runtime root. This does not authorize substituting current annotations or altering scientific arguments, inputs, thresholds or expected results.

Browser rhythm calculations have their own [circadian validation runbook](runbooks/CIRCADIAN_VALIDATION.md). It distinguishes independent numerical reference checks, null simulations and host-specific timing from biological validation. `src/circadian/jtkCycle.ts` owns canonical JTK_CYCLE support constraints and its grouped null; period-search correction is separate from gene-wise correction. GSE157077's time-series unit correction preserves all expression values, with its bounded lineage under `data/quality/gse157077-timeseries-unit-2026-10-23/` (restored by `pnpm run fetch:data`).

The shared study record is `StudyFactTable` in `src/common/StudyMetadata.tsx`; the library's study record and the Explorer's dataset information panel both use it. Current quality badges read `src/data/datasetQualityR460.ts`: Pipeline QC, Experimental design and Author concordance are separate decisions. The sealed `datasetQuality.ts` and original combined `internalQc` assessment remain available for historical audits. See [the verification guide](../data/author-validation/README.md) and [CONTEXT.md](../CONTEXT.md).

## Health Stack

- type-check: tsc --noEmit (via `pnpm run typecheck`)
- lint: biome lint
- test: vitest run
- deadcode: knip

The codebase is **TypeScript, strict** for the app and tests, lenient for Node scripts (`tsconfig.json`, `tsconfig.node.json`); `pnpm run typecheck` runs both. The Vite build does NOT type-check, so `tsc --noEmit` is the gate. Node scripts are `.mts`, run via `tsx`. The few shell scripts under `geo_replication/scripts/` are not linted.

The configuration files (`biome.json`, `knip.json`, `tsconfig*.json`, `vite.config.ts`, `pnpm-workspace.yaml`) are the source of truth for rules, scopes and exclusions. The notes below record only why some settings are unusual.

Dependencies are installed with pnpm (the version is pinned by `packageManager` in `package.json`; `corepack enable pnpm` provides it). `pnpm-workspace.yaml` lists the packages allowed to run install scripts and the patched dependencies. pnpm 12 passes a literal `--` through to the script, so pass script arguments directly: `pnpm run upload:bundles --dry-run`. pnpm does not hoist undeclared packages, so a script that imports a package must list it in `package.json`. For the same reason `workbox-window` is declared: `vite-plugin-pwa`'s `virtual:pwa-register` imports it from the project root.

SheetJS (`xlsx`) is installed from the SheetJS CDN tarball, because npm stopped at the vulnerable 0.18.5. `patches/xlsx.patch` adds a `node` export condition so Node resolves `import XLSX from 'xlsx'` to the CommonJS build, as it did under 0.18.5. Without it Node loads the ES module build, whose `readFile` cannot reach the file system and has no codepage tables, and the sealed evidence producers that read author workbooks fail. Browser bundles still use `xlsx.mjs`. Re-check the patch when moving to a new SheetJS version.

`tsc` is TypeScript 7, the native compiler, which has no JavaScript compiler API. Code that parses TypeScript in Node (`scripts/agent-context/source.mjs`) imports `@typescript/typescript6` instead of `typescript`; knip 6 parses with oxc and needs neither.

knip's project scope is `src/`, so an export that only `scripts/` imports carries a `/** @public */` tag. The sealed `datasetQuality.ts` is excluded from export findings only (other knip checks still apply) because its bytes are pinned by the reader review, and imports of maintainer-held evidence readers are allowed to stay unresolved on a public checkout. knip loads `vite.config.ts`, which reads the gitignored `public/query/` catalog, so run `pnpm run fetch:query` first on a fresh checkout; without it knip reports false positives. CI runs `pnpm run deadcode`.

Both `tsc` configs are incremental, with build info in the ignored `.tmp/tsc/`; delete that directory to force a full check.

Biome force-ignores (`!!`) the evidence, tool and checkout trees listed in `biome.json`; a single `!` would still let its scanner traverse them.

Test files ending in `.ts` run in Vitest's Node environment and `.tsx` files in jsdom (`test.projects` in `vite.config.ts`). A `.ts` test that needs a DOM or the production bundle transport starts with `// @vitest-environment jsdom`; without a DOM, `bundleSource` reports every load as failed. The Node group runs first, so its slow evidence checks do not wait behind every component test.

jsdom stays on 26. Later versions give `span` its correct `inline` display, so Testing Library joins a label and its count (`Aging` + `<span>12</span>`) into one word. In the browser those buttons are flex containers styled in `index.html`, whose items are blockified and named with a space, but tests load neither that stylesheet nor any layout. Upgrading jsdom therefore needs explicit spaces in those accessible names first; 25 component tests fail without them.

On a busy Windows machine, run `pnpm test --maxWorkers=2` if Vitest reports `Timeout calling "onTaskUpdate"`. This runs the same suite with fewer concurrent workers.

The September 11 author comparisons pin the exact bytes of `src/data/authorConcordance.ts`. Its check IDs come from the union of existing checks, so the subsequent lookup is guaranteed to exist. Biome keeps that optional-chain assertion as a warning for this file; changing it only for style would invalidate the retained evidence. The September 5 audit's `forEach` callback calls Node's void-returning `assert`; its callback-return lint diagnostic is also a file-specific warning. Other files retain the default rules.
